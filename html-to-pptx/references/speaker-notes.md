# 讲稿（Speaker Notes）改写规范

HTML 幻灯片里常见 `<div class="notes"><b>讲稿：</b>...</div>`。转换时这些讲稿要改写后写进 PowerPoint 备注页，通过 `<Slide notes={...}>` 传入。

## 硬规范（违反会被校验脚本拦下）

1. **字数 ≤ 300**。原文超长的要压缩，只留能讲清楚的主干。用 `scripts/check_notes.py slides/ --require` 校验。
2. **第一人称**：用「我 / 我们」直接讲观点，不写"本页说明……"这种第三人称。
3. **禁止元描述**：不得出现"这一页展示了 / 本页聚焦于 / 下图描述了 / 接下来进入 / 讲的时候可以 / 如图所示"。这些是对 PPT 的说明，不是讲稿。注意"建议先指定接口人"这类是**正常语义内容**，不是元描述，不要误删。
4. **删除"讲稿："前缀**：HTML 里的 `<b>讲稿：</b>` 是标签，不要带进备注。
5. **分点换行**：出现"第一/第二/1./2./首先/其次"等分点逻辑，必须换行分段，不要堆在一段。
6. **推荐模板字符串**：`notes={\`...\`}`（反引号）支持多段落；讲稿里的双引号用中文引号或不转义即可。

## 改写示例（真实案例）

### 反例 ❌ —— 直接搬运 HTML 原文

```
讲稿：这一页展示了标书内容分两类。第一类跟公司资质相关，是填空，
比如项目名称、资质图片、业绩表格、人员信息，确定性高，适合程序做。
第二类跟公司资质关系不大，比如技术方案，需要根据招标文件写，有不确定性，
适合 AI，但必须人审。如下图所示。讲的时候可以先讲第一类。
```

问题：带"讲稿："前缀、有"这一页展示了/如下图所示/讲的时候"元描述、第三人称、超长。

### 正例 ✅ —— 改写后

```
我把标书内容分成两类。一类跟公司资质强相关，比如项目名称、资质图片、
业绩表格、人员信息，确定性高，适合程序做，也就是填空。另一类跟公司资质关系不大，
比如技术方案，要根据招标文件写，有不确定性，适合 AI，但必须人审。
技术方案更依赖业务判断，这也是后面我为什么会说需要业务同事参与。
```

改写要点：去前缀、第一人称"我"、删掉所有对 PPT 的说明、末尾自然补一句页面没展开的背景。

### 分点讲稿正例 ✅

```
今天我讲四块。
第一，为什么现在做，标书现在是怎么做的。
第二，标书内容怎么理解，哪些能交给程序，哪些要靠人。
第三，时间账和我的初衷，为什么我想把这件事往前推。
第四，目前的进展、遇到的困难，以及需要一起讨论的事。
今天我不急着要资源，先把事实讲清楚。
```

分点用真实换行分段（反引号字符串里的 `\n`），不堆在一段。

## 多页内容一致性陷阱

改稿时（如目录树加了一层分类），正文、目录树图形、讲稿**三处都要同步**。真实踩过的坑：只改了树和正文，讲稿还停留在"历史标书按目录放"，与新的"先按类型分类"不一致。改完用 `scripts/inspect_html.py` 重新解析，逐页比对讲稿。
