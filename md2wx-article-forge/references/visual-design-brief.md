# 视觉设计基准（组件库 / 工作流 / 差异化铁律 / 完整案例）

## 0. 本文档是什么

本文件是**排版视觉的唯一权威规范**，自包含：只描述「该长什么样、何时用什么、什么不许做」。
写 markdown 的人按第 3 节选角色、按第 4 节守铁律；设计主题时按第 1 节分层、第 4 节查重；
检查成品时按第 3、5 节对照。**谁在哪个阶段执行这些规则，见 SKILL.md 的派工协议，本文不涉及。**

用户提供的原始设计 prompt 已**原样存档**于 `references/visual-designer-original-prompt.md`
（含案例 A 完整 HTML）。本文件是其执行版：所有数值与命令均引自项目真实文件，可逐项复验。
原文条目与本项目实现的逐条对应见第 6 节对照表。

## 1. 分层：markdown 定角色，json 定样式，脚本出码

这是全流程最关键的职责切分，**违反它就是返工的起点**：

| 层 | 决定什么 | 不决定什么 |
|---|---|---|
| **markdown 层**（`:::role` 指令、`**加粗**`） | 这段是哪个角色：`:::lead` 还是 `:::pain`；哪些词是锚点 | 不写色值、不写 CSS |
| **主题 json 层**（`assets/themes/*.json`） | 每个角色长什么样（色板/圆角/阴影/边框） | 不判断文字属于哪个角色 |
| **脚本层**（`render.py` / `typeset.py`） | 按主题把样式盖成内联 HTML，过微信白名单 | 不做任何视觉判断 |

理由：**写 markdown 的人只需要写 `:::card`，不需要知道色值**（`render.py` 注释原文）。
样式写死在主题 json 里，改视觉 = 改 json，不用动文章、不用重新理解内容。

## 3. 视觉组件库（9 个角色）

写 markdown 时用 `:::role` 开头、`:::` 收口。支持嵌套（`:::module` 里可嵌 `:::note`，
`render.py` 用 depth 计数配对，内层 `:::` 不会误关外层）。

值取自 `assets/themes/critique.json`（深蓝审稿风）：

| 角色 | 什么时候用 | 视觉形态（critique.json 实际值） |
|---|---|---|
| `lead` | 开篇一句话定性 / 摘要 | 渐变灰蓝底 `linear-gradient(135deg,#f5f7fa,#e9edf5)`，padding 12/14，圆角 12 |
| `pain` | 痛点、问题清单 | 米黄底 `#fff8f0` + 左侧橙条 `#e67e22 4px`，padding 10/12，圆角 8 |
| `module` | 一个独立模块的容器 | 白底 + 阴影 `0 2px 12px rgba(0,0,0,.06)`，padding 12，圆角 12 |
| `note` | 补充说明 | 浅蓝底 `#eef6ff`，padding 8/10，圆角 6 |
| `warn` | 风险提醒 | 浅红底 `#fff0ed`，padding 8/10，圆角 6 |
| `cost` | 成本 / 代价 | 浅黄底 `#fef9e7`，padding 8/10，圆角 6 |
| `fact` | 客观事实数据 | 灰底 `#f2f3f5`，padding 8/10，圆角 6 |
| `verdict` | 终审结论 | 深蓝黑底 `#1e293b` + 浅字 `#e2e8f0` + 强调黄 `#facc15`，居中，圆角 14 |
| `footer` | 结尾落款 / 免责 | 灰字 `#999999`，**无背景无边框**，居中 |

另一主题 `default.json` 是绿调，角色相同、色值不同。

**色彩语义**（选组件就按这个对号）：蓝底=信息、红底=质疑/警示、黄底=代价、灰底=事实。

**正文基准**：15px / 行高 1.7em / 色 `#2e2e2e`；h1 24px、h2 20px、h3 18px，主色 `#1e3b5a`。
（这套数值是踩过坑定下来的：收紧前留白占比 33%、最长空洞 51px，收紧后降到 18% / 21px。）

**markdown 层的视觉锚点写法**（决定成品质感的关键）：
- **段内关键词高亮**：每个长段落把总结性、判断性、强观点的短语（通常 10 字以内）
  用 `**加粗**` 标出，**每段至少 1–2 处**——渲染器自动给粗体上主题色，
  读者 3 秒就能抓住段落核心。
  例：本质是 **UX 工作流的工程缝合**与领域知识显性化封装。
- **编号卡片**：原文是"问题 1/2/3"结构的，编号照写（`**问题 1：**`）配 `:::pain`，
  渲染出"编号加粗 + 左竖线 + 警示底"三位一体。
- **字段型内容**：「大白话翻译」「隐藏代价」等字段选对应容器 + 加粗前缀
  （`:::note` + `**大白话翻译：**`）。
- **终审结论**：全文收束用 `:::verdict`（深色逆卡片，结论短语加粗出金色强调，
  形成"标题金 / 结论亮 / 叙述浅"三层视觉）。
- **标题组**：主标题用一级标题；副标题写在标题下第一行或 `:::lead` 首行，
  不要另造 h2——副题是说明文字，不是章节。
- **克制**：emoji 前缀、分割线适度即可，不可过量。

## 4. 差异化铁律（反模板）

**同一公众号连续几篇用同一套配色 = 读者认不出这是新文章。** 所以：

1. **正文字号下限 14px**（低于此移动端不可读，`theme_lint.py` 硬拒）
2. **每个组件必须有视觉形态**：有背景，或有边框，或有差异化文字色
   （`footer` 无底无框但用了灰字，合法——这条规则当初误伤过 footer，实测后修正）
3. **与历史主题查重**：新主题和历史主题色集合 Jaccard ≥ 0.6 拒登记；组件形态完全相同也拒
4. **结构维度也要轮换**（机器查不了，设计新主题时人工遵守）：
   左竖线 → 顶部色条；暖色系 → 冷色系；大圆角 → 微圆角；阴影深浅切换；渐变背景 → 纯色背景。
   **连续两篇用同一套"卡片结构 + 配色"就是模板化，读者会腻。**

执行者是脚本，不是人肉：
```bash
python scripts/theme_lint.py <新主题.json>
```
实测：把 `critique.json` 改名 `fake.json` 提交 → 相似度 1.00 被拒；正常新主题 0.35 通过。

## 5. 完整案例 A（md 输入 → 真实 HTML 输出）

### 输入（真实文件 `assets/fixtures/critique.md` 开头）

```markdown
:::lead
**一句话定性：**把现成的 LLM 塞进「专家技能库 + 多智能体路由」的提示词工程外壳里，
本质是 **UX 工作流的工程缝合**与领域知识显性化封装。
:::

# 组件化排版样例

本文用于验证 `:::role` 容器指令、标题降级与深色终审卡片。

## 核心痛点账单

:::pain
**问题 1：**现有工具反馈颗粒度粗糙，且脱离 LaTeX 源码层面的精确定位。
:::
```

### 输出（`typeset.py --theme critique.json` 真实产物，未改一字）

```html
<section style="background: linear-gradient(135deg, #f5f7fa 0%, #e9edf5 100%); padding: 12px 14px; border-radius: 12px; margin: 12px 0px"><p style="font-size: 15px; color: #2e2e2e; line-height: 1.7em; letter-spacing: 0.5px; margin: 2px 0px; text-align: justify"><strong style="font-weight: 700; color: #1e3b5a">一句话定性：</strong>把现成的 LLM 塞进「专家技能库 + 多智能体路由」的提示词工程外壳里，</p><p style="font-size: 15px; color: #2e2e2e; line-height: 1.7em; letter-spacing: 0.5px; margin: 2px 0px; text-align: justify">本质是 <strong style="font-weight: 700; color: #1e3b5a">UX 工作流的工程缝合</strong>与领域知识显性化封装。</p></section><p style="font-size: 24px; font-weight: 700; color: #1e3b5a; line-height: 1.4; margin: 10px 0px 6px 0px; letter-spacing: 0.5px">组件化排版样例</p>
```

**这段示范了三件事**：
- `:::` 组件 → `<section>` 内联样式容器，**没有 class**（微信会剥）
- 卡片内段落 margin 收到 `2px 0px`（普通段落是 `10px 0px`）——这就是"卡片内不再有巨大空洞"的来源
- `<strong>` 用主色而非纯黑，这是组件的强调层

### 公式案例（行内 / 块级）

md 里 `质能方程 ![inline](eq3.png) 是……` 渲染为：

```html
质能方程 <span><img src="eq3.png" alt="inline" style="max-width: 100%; height: 13px"></span> 是物理学中最著名的公式之一，
```

注意 `height: 13px` 是渲染器读 PNG 头算出来的（300dpi → 96dpi × 0.9 折算）。
**不要手写这个高度**：早先手动合并的结果是 E=mc² 显示 45px 高（正文 3 倍），像贴了块膏药。

## 6. 原文 → 实现对照表

原文的活按**层**落位（层定义见第 1 节）。状态列：✅ 已落地 / ⚠️ 部分落地 / 架构差异。

| 原文条目 | 本项目实现位置（按层） | 状态 |
|---|---|---|
| 第 1 步 审稿（调性/情绪关键词/结构扫描） | markdown 层：调性写入 `1_baseline.json` 的 `tone`/`mood_keywords` 字段；组件选择贴调性 | ✅ |
| 第 2 步 定调（主色板/卡片风格轮换） | 渲染期：读 tone 字段 → 查 `registry.json` 上篇主题 → 沿用别的 / 换 / 按调性造新主题过 lint；样式本体定义在主题 json | ✅ |
| 第 2 步 轮换的机器保障 | `theme_lint.py`：色值查重（Jaccard≥0.6）可机器执行；**结构维度轮换查不了**，靠第 4 节铁律第 4 条人工遵守 | ⚠️ 部分 |
| 第 3 步 构架（拆段/高亮/标签） | markdown 层：视觉锚点写法（见第 3 节） | ✅ |
| 第 3 步 视觉钩子（标题下划线/印章感） | 主题 json 层：造新主题时的样式设计 | ✅ |
| 第 4 步 出码（AI 手写内联 HTML） | 脚本层：`typeset.py`。AI 手写 HTML 不可复现、易错，改脚本 | ✅ 架构升级 |
| 第 5 步 设计说明 | 不需要：主题 json 本身就是声明式设计说明 | 架构差异 |
| 卡片容器 / 色彩编码 | markdown 选角色（`:::lead/pain/module/note/warn/cost/fact`）+ json 定色 | ✅ |
| **段内关键词高亮**（每段 1–2 处 10 字内短语） | markdown `**加粗**` → 渲染器自动上主题色 | ✅；⚠️ 警示色高亮（原文暗红 #c0392b）暂无独立语法，粗体只有主题色 |
| 标签化小标题（💬 大白话翻译） | markdown：容器组件 + 加粗前缀（`:::note` + `**大白话翻译：**`） | ✅ 等价落地 |
| 左竖线强调 | `:::pain` 的 border-left 4px | ✅ |
| 编号痛点卡片（编号+竖线+背景） | markdown：`:::pain` + `**问题 1：**` | ✅；⚠️ 编号暂用主题色而非原文的暗红警示色 |
| 深色逆卡片三层视觉（标题金/结论亮/叙述白） | `:::verdict`（`strong_color: #facc15`） | ✅ |
| 装饰元素（emoji 前缀/分割线，克制） | markdown 层 | ✅ |
| 页脚声明（灰字居中 12–13px） | `:::footer` | ✅ |
| 内容处理边界（不改核心判断） | 内容保真红线（SKILL.md 阶段红线表） | ✅ |
| 标题组（主标题 22–26px + 副标题 14px 灰） | 主题 json `h1_size: 24px`；副题写法见第 3 节 | ✅ |
| 技术要求（内联/无 class/对比度/320–428px） | 脚本层：`wechat_rules.py` + 渲染器 | ✅ |
| 案例 A 完整 HTML | 原文存档（对照溯源）+ `work/demo/2_case.html`（本项目渲染器产物） | ✅ |

**总结：原文一条流水线上的五种活，按层落位——markdown 层（语义标记）、

## 7. 常见错误

| 错误 | 后果 | 正解 |
|---|---|---|
| 在 md 里写 `<div style=...>` | 微信剥掉样式，卡片变裸文字 | 用 `:::role`，让渲染器产出 `<section>` |
| 给组件手写色值 | 主题换了全篇色乱 | 只写角色，色值留 json |
| 用 h4-h6 表达层级 | 渲染器降级 + 告警 | 层级压到 3 级，其余用加粗小标题或 `:::note` |
| 图片路径与 html 不同目录 | 全部裂图（真实事故：4 张全裂） | `--png-dir` 设为 md 同目录，md 与 html 同目录 |
| 觉得不好看就手改 HTML | 下次渲染覆盖，白改 | 改 md 或改主题 json，重跑 typeset |
