# 四级证据与台账（简版规约）

完整规约在 `../autodl-remote-shell/references/capability-matrix.md`，本文只保留本 skill 的入口要点。
**详细方法论在那边，本文件不复制正文**，避免两处失同步。

## 四级证据（每条结论都必须标）

| 等级 | 含义 | 在本 skill 的典型来源 |
|---|---|---|
| **实测** | 本次实例真跑出来、可复验 | L4 受控实测日志、`curl /health`、`/proc/<PID>/cmdline`、`nvidia-smi` |
| **源码** | 读到函数签名 / config / `--help`，未做行为验证 | L1 启动脚本、L3 config |
| **官方** | 社区页 / README / 模型卡声明，未本机复验 | L0 应用名、L1 镜像描述 |
| **未核实** | 没有可靠来源，**留空不猜** | — |

**判读边界**：「源码里有参数」≠「效果已验证」；「官方声明」≠「本机实测」；
同一行多个镜像必须同口径；产物规格以产物为准，不抄配置。

## 台账最小字段

复制 `scripts/analysis-ledger-template.json` 到项目目录再填。结构只有三处：

- `models`：候选镜像，每条 `{key, label, sub}`。
- `rows`：维度行，每条 `{group, dim, level, values, evidence}`。`evidence` 必须指到文件 / 命令输出 / 行号。
- `scene_map`：场景 → 关键维度的映射，决定下一步补测什么。

维度是**开放的**：加维度就往 `rows` 追加，加镜像就给每条 `values` 补同名 key。
模板里的示例行只说明结构，不是必须填的维度，也不是结论。

## 数据放哪

判据是「换一台机器还成不成立」，不是「是不是数值」：

- 换机器仍成立：模型固有规格、带条件的量级范围 → 规格卡（可进 skill），带版本与来源。
- 换实例就失效：磁盘余量、单次测速、pip 源、PID、榜单 → 项目台账。
- 同一镜像不同条件下的实测值**并列写、标条件**，不拿新值覆盖旧值。

## 按消费时点分视图

这份与「数据放哪」是两个正交维度，别混成一个问题：

| 时点 | 消费方在做什么 | 该看到什么 |
|---|---|---|
| 看结果 | 判断好不好、值不值 | 结果矩阵 + 直接相关元信息；规格只留一个入口链接 |
| 选型 / 复盘 | 判断能不能装、能否对齐场景 | 规格台账、证据等级、场景映射 |
| 定方法 | 决定怎么测、怎么切输入 | 对照实验的多个 arm 与判据（需要时才做第三页） |

判据是「此刻这个人需不需要它」，不是「信息有没有用」。
报告里「镜像宣称」与「本机实测」分栏，别让看结果的人先扫过一堆选型字段。
