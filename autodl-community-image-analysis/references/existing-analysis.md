## 这些分析对本 skill 意味着什么

- **验「提速」**：直接继承测速三前提；不要把冷启动 / 单 prompt 复读的读数当结论。
  镜像名里的「500」先按 L0 定为「口径未定义」，再决定测什么指标。
- **验「高画质」**：继承「软控制 / 硬控制」的判据（见 capability-matrix.md）——
  画质需要固定输入输出对照，并写清是主观判断还是客观指标；不能从配置文件反推效果。
- **验「某版本 / 某框架」**：走 L1 静态信息 + L3 运行时事实，两者不一致时以 L3 为准。
- **跨镜像横评**：复用台账方法，但维度按当前候选临时组织，不照抄上一个项目的表。

## 最新实证（2026-11-25，MINIMAX-H3 镜像）

**可迁移的判据**（不是结论数字）：

- **单次 A/B 的方向会被顺序偏差整个翻转**：本镜像初测「加速版 1.76× 更快」，预热 3 次 +
  A→B→A→B 交叉后反转为「加速版慢 25.8%」。教训：**任何未交叉的单次加速倍数都只能标"上界观察"**，
  不能写进结论，更不能据此宣传镜像。
- **SSH 不通不等于测不了**：面板可达时，从 JS bundle 抽 `/api/comfy/proxy/*` 端点即可跑完整
  原生 API（提交 / 轮询 / system_stats），显存峰值从 `system_stats.devices[].vram_total - vram_free`
  每秒采样替代 `nvidia-smi`。详见 `usage-guide.md`。
- **整包工作流对照只能测"方案差异"**：两版 steps / 采样器 / 节点数都不同，
  测到的是整包差异，不能归因到某个加速开关。

**不可迁移**：那台 3090 上的墙钟秒数、显存 MiB、具体工作流名与面板地址。

## 边界声明

- 上表是**一次实证 + 一套方法**的索引，不是社区镜像的通用检查清单。
- 「官方示例」和「镜像名」都是精心挑过的，拿它当统一考题会有主场优势；候选文本与测试条件需自行定义。
- 新增镜像时只重跑受实例影响的层（L2~L4），L0 拆法与 L5 归档规约可直接复用。
