# 设计原则（为什么这套流水线长这样）

> 本文管「**为什么**」，不含操作规则：操作看 SKILL.md 的执行顺序表，
> 具体判断看对应 reference。来源：DESIGN.md（初版设计稿）甄别后仍成立的
> 原则，加实测教训。主 agent 演进本文档，用户否决制。

## 1. 确定性进代码，只有判断进文档

**谁执行它，就放谁旁边**：

| 内容 | 谁执行 | 放哪 |
|---|---|---|
| token 计量 / 分块 / 剔除 / 成本 / 查重 | 脚本 | `scripts/` |
| 术语条目本身 | `bundle` 投影 + 执行 agent 遵守 | `data/glossary.yaml`（唯一真相源） |
| 翻译时的判断（语序、拆句、gloss） | 执行 agent | `references/execution-rules.md` |
| 流程编排判断 | 主 agent | SKILL.md |

凡是能枚举的规则绝不写进提示词：代码 100% 可复现、零 token、不漂移；
提示词里的规则每轮判断都可能变样（同一术语这轮一个译法下轮另一个）。

**主 agent 的升级路径：编排者 + 工具匠。** 主 agent 不产出译文类产物；它自己的
重复性手工动作（同一段 grep / 组装 / 计数出现第二遍）要固化为 scripts/ 下的脚本
或 shell 命令 —— `chunk.py cost`、sections 底账、`reconcile` 都是这么诞生的，
check.py 是下一个。现有脚本不够用时，主 agent 有权直接新增脚本，遵循既有纪律
（fresh-env 可跑、自包含、同步 README 与测试），无需逐次请示。判断类动作
（分类、裁定、否决处理）不在此列 —— 那是它存在的理由，不该脚本化。

## 2. 单一真相源，规则只写一次

`glossary.yaml` 只有一份，脚本和 agent 都读它，不在 prompt 里背副本 ——
重复列举 = 两份真相 = 必然不同步。文档同理：每个"为什么/怎么做"只有
一个权威位置，其它地方只放链接。

## 3. 优先级链

**用户裁决 > 累积词典（lexicon）> 术语表（glossary.yaml）> 风格判断**。

lexicon 高于 glossary 是因为 lexicon 是本 run 里刚发生的事实（前几块
已定的译法），先对齐本篇，再谈稳定术语。

## 4. 隔离靠构造数据，不靠口头禁令

执行者拿着文件系统工具，「禁止读其他文件」是君子协定。真隔离是**把需要的
内容由程序拼进自包含 bundle**（规则 + 命中术语 + lexicon + 示例 + 锚点 +
本块原文），读完一个文件就够了，没有理由也没有必要打开别的。
分块纪律（§8 of chunking-and-cost.md）存在的唯一目的：让「拼接后是否连贯」
变成可证伪的问题。

## 5. 文档是活的：谁有权改哪份

| 角色 | 能改 | 绝对不能改 |
|---|---|---|
| 用户 | 任何文档，一句话生效 | — |
| 主 agent | references/*、glossary.yaml、examples.md（先行落盘，用户否决制） | 本表约束本身（改它要用户点头） |
| 执行 agent（翻译） | 只产出译文 + 回执报告 | **任何说明文档** |
| 评估 / 修订 agent | 只产出报告 / 译文 + 回执（含**规则缺口报告**，review-and-revise.md §5） | **任何说明文档**（同执行 agent） |

执行层不能改文档的理由：标准一旦能自我修改，就会逐轮放松 —— 多写者必然
漂移（实测：同一术语被译成「人在环路中」和「人在环路」）。评估 / 修订 agent
同理，外加两条：它们是只见局部的临时角色，判断不了缺口是个例还是惯例；
run 中途改规则会让后续 bundle 变样，流程不幂等。

主 agent 的变更来源：用户反馈、多 run 重复出现的问题（≥2 次才动表，单次是
个例）、**评估 / 修订回执的规则缺口**（同一缺口 ≥2 篇，闭环见
review-and-revise.md §5）、扫描候选（scan_corpus.py）。废弃条目标
`[已废弃 · 原因 · 日期]` 不删除 —— 保留历史才能解释这条为什么曾经存在。

## 6. 人工反馈的定位：默认自主，反馈是加速通道

**原则：没有人工反馈，全流程照样跑完出稿。人工反馈是加速纠偏的可选通道，
不是流程的启动前提。** 每步等人点头的流程没有存在价值 —— 人看一眼就能指出
的问题，不需要一套机制去等。

| 路径 | 触发 | 阻塞？ |
|---|---|---|
| **自主执行（默认）** | 翻译 → 评估 → 修订 → 确定性验收，一路走完 | 否，无人也跑完 |
| **人工反馈（可选）** | 四个入口：成本确认（>30000）/ 分派表否决 / 术语否决 / 交付后单点重翻 | 到了就吸收，没来就照跑 |

用户的永久性裁决（"agent 就翻成智能体"）由主 agent 写进 `data/glossary.yaml`
或本文档体系 —— 一句话生效，所有后续篇目自动沿用，不逐篇重复。

**自主的副作用必须防**：没有人在场时，质量验收必须**确定性**（术语 grep +
守恒计数），评估收死在硬错误（§8）—— 风格判断留给交付后的人。让一个模型
评估另一个模型，提的"问题"里大量是风格偏好；自主流程若把风格偏好当错误修，
有节奏的表达会被磨成四平八稳的平庸中文，质量反而下降。

## 7. 已否决的设计（防止将来重新提议）

| 被否决方案 | 否决理由 | 现行替代 |
|---|---|---|
| 三 agent **无条件全文多轮循环**（评估→修改逐轮收敛到 3 轮，全文重评） | 过早优化：零样本时评估标准只能凭空编；全文重评 12k/轮预算扛不住；风格噪音随轮数放大，来回改磨平节奏 | 质量主体靠事前预防（术语投影/词典/锚点）+ 确定性校验；评估职能保留为**有界循环**（评估→修订→按幅度复核被改块，封顶 2 轮评估，review-and-revise.md §1.3，2026-10-07） |
| 预处理 agent | 预处理 95% 是确定性工作（HTML 转换/URL 抓取/章节剔除/token 计量），已在代码里；唯一判断点（无结构文本的标题/格式判定）已由「sections.py detect 出候选 + AI 分类标题清单（~1k tok）+ mid 项列给人」覆盖 | 现行 SKILL.md 执行顺序第 1–3 步；新增输入形态时加**脚本**（如 docx 样式映射），不加 agent |
| 翻译结果回写源文件 | 源被写就不再是源，重跑不幂等，无法对照校验 | 源只读，译文一律落 outputs/ |
| outputs/<run_id>/round_N 快照目录 | 随循环方案一起作废 | outputs/ 平铺：<名>.source.md + chunks-XX/ |
| 「下载 agent」「按职能切 agent」 | 下载是确定性代码，塞给 agent 只加成本加不确定性 | fetch.py 等脚本；agent 数量由判断类型决定，不由任务量决定 |

## 8. 远期待建的依据（不是凭空编规则）

- **check.py 硬检查**（keep 违规 / 单位换算 / 链接失效 / 代码块被改 /
  结构守恒计数）：5–10 篇之后再建 —— 没见过真实错误就写检查等于编规则。
  结构守恒计数（标题/链接/图片/公式块）已两次实测抓到真缺陷，是第一项。
- **评估只查硬错误，不评风格**：让模型评估模型，提的"问题"里相当一部分
  是风格偏好；风格判断交给人 —— 人看一眼比模型判三轮准。已落地为单轮终审
  （references/review-and-revise.md，2026-10-07）：检查范围收死在漏译/多译、
  术语违表、单位换算、链接图片丢失、代码块被改、结构破损；修订只做一轮，
  验收靠确定性校验（术语 grep + 守恒计数），不回炉评估。
- **数据程序化构造**：术语候选靠扫（scan_corpus.py），不靠"想起一条写
  一条"；已确认条目记录来源（用户裁决 / 重复出现 / 扫描）。
