# 分块、成本与隔离

> 本文管「长文怎么切、钱怎么算、块间怎么保持一致」。翻译判断准则与硬边界见
> execution-rules.md；论文按节取舍见 paper-disposition.md。

## 1. 长文：先分块，再串行翻译

整篇一次翻太长会退化（后半段术语漂移、漏译、结构走形），但按字符数粗暴切断会把
句子、代码块、表格切碎，拼起来读不通。所以用 `chunk.py` 按结构切：

```bash
python skills/translate-zh/scripts/chunk.py count <md>                   # 看 token 数，决定要不要分块
python skills/translate-zh/scripts/chunk.py cost  <md>                   # 成本估算 ← 开翻前必跑，见 §2
python skills/translate-zh/scripts/chunk.py split <md> --out-dir <dir>   # 按标题/代码块/表格边界切块
python skills/translate-zh/scripts/chunk.py bundle <dir> --index N       # 生成第 N 块的自包含任务包 ← 用它，别用 context
python skills/translate-zh/scripts/chunk.py join  <dir> -o final.zh.md   # 全部翻完再合并
python skills/translate-zh/scripts/chunk.py reconcile final.zh.md        # 合并后统一清单项的重复译法
```

- **阈值默认 5000 token**（装了 tiktoken 就精确计数，否则启发式估算，宁可高估）。
  2026-10-07 由 2800 上调：4319 / 6435 token 两次整翻实测无退化（术语零漂移、
  公式字节级一致、结构守恒）；原 2800 是保守设计值，无实测悬崖依据。
- **≤ 阈值 → 整篇一次翻完**，不要分块。**整翻的产物路径**：执行 agent 直接写
  `outputs/<名>.zh.md`（主 agent 在派工单里明确此输出路径）；翻完仍要跑
  `reconcile`（全文清单项统一）+ `conservation`（守恒校验）。split/join 不适用
- **> 阈值 → 串行翻**：切块保证不切断代码块、表格、标题；**单个超长段落宁可单独成块，也不切碎**
- **两种形态都外派全新执行 agent**（固定开销实测几乎一样：bundle ~5.4k / 整翻四件套 ~5.5k）。
  整翻外派 = 文件清单式：执行 agent 只读 `references/execution-rules.md` +
  `data/glossary.yaml` + `data/examples.md` + 全文这 4 个文件（无 lexicon ——
  那是分块过程的累积产物，整翻不存在）。**主 agent 永远不亲自翻译**：它的上下文
  已有全套编排知识（底账/分类/回执），再塞原文只会稀释注意力，且"知道全文"会让
  翻译无法用锚点机制证伪（见 §8）

## 2. 成本闸门 C-0（先于一切翻译动作）

**任何内容开翻之前，必须先跑 `chunk.py cost <md>` 并把估算展示给用户。** 分块不省
token —— 每一块都重复付一次固定开销（规则 + 术语投影 + 示例 + 锚点，实测 ~5500），
长文的分块总账可以是整篇的 3 倍，这笔账必须让用户在开翻前看到。

- 预估总消耗 ≤ 30000 token：可翻
- **预估 > 30000 token：必须得到用户对这份估算的明确确认，才许派第一个执行 agent** ——
  没有确认就开翻 = 违规，无论文章多值得翻
- 用户表示预算紧张时，优先给**部分翻译**选项（只翻摘要 / 摘要+结论 / 指定章节），
  而不是默认整篇 —— 摘要通常几百 token，几乎免费
- fetch（下载）不耗 token，OCR 走用户自己的服务，这些不在本闸门范围；
  本闸门管**所有 LLM 派工动作**（标题分类 / 翻译 / 终审评估 / 修订）。
  **闸门口径（2026-10-07 澄清，消除与 review-and-revise.md §3 的歧义）**：
  展示给用户并对照 30000 的总账 = 翻译 + **首轮**全文评估 + 首轮块级/单块复核；
  若评估发现硬错误触发了**第 2 轮全文评估**，那是计划外的追加派工 ——
  执行前单独向用户补一次确认（2 轮是封顶，账最多翻倍一次，可预期）

## 3. 翻译模式 C-0-1：预算决定模式，模式决定动作

一对一全翻不是唯一选项。**减源量是唯一线性的省钱杠杆**（每删 1k token 源 ≈ 省 2.2k
总量），所以在开翻前先和用户确认模式：

| 模式 | 适用 | 动作 | 量的关系 |
|------|------|------|---------|
| **full** | 用户明确要完整译文 | 逐段 1:1 全翻 | 输出 ≈ 源 × 1.2 |
| **digest** | 快速读懂论文/长文 | 结构保留（标题层级、图表引用、公式、代码）；核心叙述章节全翻；**实验/分析压缩成中文要点**（每节 3–5 句）；参考文献剔除 | 输出 ≈ 源 × 0.3–0.4 |
| **abstract** | 只想知道讲了啥 | 只读摘要+引言+结论（≈前 2 页+末页），输出 300–500 字中文摘要 | 输入 ≈ 源 × 0.2，输出 <1k |

**压缩与翻译的关系（防任务干扰，两条规则）**：

1. **每一节的「压缩成中文要点」是一次独立调用、单一任务**：读该节英文原文，直接产出
   中文要点。不要拆成「先英文压缩、再翻译压缩稿」两步 —— 付两次输出、两次固定开销，
   中间英文产物没有任何用途。
2. **严禁一个调用里混排多种模式**：全翻的节走全翻管线，压缩的节走压缩调用，绝不把
   「第 3 节全翻 + 第 4 节压缩」塞进同一次输出 —— 翻译要求逐句忠实，压缩要求取舍删减，
   两种指令混在一次生成里互相拉扯，两边都做不好。

本项目的架构天然满足第 2 条：每次调用都是 bundle 出的自包含任务包喂给**全新 agent**
—— 摘译 agent 的任务包里只有压缩规则，根本不知道全翻规则的存在。**隔离即防干扰**，
不存在「一个模型同时干两件事」。

**分块纪律不因省钱豁免**：digest/abstract 减的是「翻多少」，不减「怎么翻」。
减量汇总后的源 >5000 token 照常 split / bundle / 锚点 / 隔离 —— 分块保的是翻译质量，
省钱靠减量，两条线不交叉。压缩调用不受分块纪律约束（输出短，一节一次调用即可，
读 8k token 的实验节出 300 字要点毫无压力）。

**分离 → 分派 → 汇总 → 翻译的执行顺序**（digest 模式）：

1. **正则找标题 + 量底账（零 token）**：`sections.py list <md>` —— 标题由纯正则提取，
   每节 token 数由代码累加，可枚举的剔除类（References 等 9 类）直接标「跳过」。
   **「哪些能删」不需要 AI** —— 删除规则已全部在代码里，正则不命中就原样保留（幂等）。
2. **AI 只做分类（约 1k token，一次性）**：把第 1 步的标题清单（**只有标题行，
   不含节内容**）交给一次分类调用，对每个「保留」节标注 full / digest / skip。
   判断只看标题语义（"5 Experiments" → digest），不读正文，所以消耗与论文页数无关。
   主 agent 先行给出分派表，用户是否决制。
3. **按表执行**：full 节照常全翻管线；digest 节每节一次独立摘译调用（见上方两条
   防干扰规则）；skip 节由 `sections.py strip` 剔除。
4. **汇总 + 复核**：分派表让 `chunk.py cost --factor` 从「拍系数」变成各节 token
   加出来的精确值（full 节计 1.0，digest 节计压缩后的实际产出量）；超确认线仍需
   用户明确确认。
5. 减量汇总后的源 >5000 token 照常分块 —— 减量不豁免分块纪律。

digest 的分界（哪节压缩、压到几句）由主 agent 判断并在译文头部声明取舍清单，
用户不同意某节的压缩力度，指出后单节重翻。

## 4. 隔离靠 bundle，不靠口头禁令

执行者拿着文件系统工具，「禁止读其他文件」是君子协定。真正的隔离是**把需要的内容
由程序拼进一个自包含包**：

```bash
python skills/translate-zh/scripts/chunk.py bundle <dir> --index N     # 产出 <dir>/NNN.task.md
```

包里已经包含：规则、本块命中的术语子集、**累积词典** `lexicon.md`、示例、上一块锚点、
本块原文。**读完这一个文件就够了**，没有理由打开任何别的东西。

## 5. 累积词典 lexicon.md（防术语漂移）

`bundle` 会自动带上 `<dir>/lexicon.md`。它是前面几块执行者回报的临机术语汇总，
**优先级高于一切**。

每块翻完，把新术语追加进去后再 bundle 下一块。实测必要性：同一个
`human-in-the-loop` 在相邻两块里被译成「人在环路中」和「人在环路」，读者会以为
是两回事。

## 6. 合并后必须 reconcile（防重复段落漂移）

即使术语全部统一，**全文刻意重复的段落仍会逐块漂移**。实测：一篇文章首尾重复的
TL;DR 六条，在没有全文视野的情况下被重译成六个不同版本（一致度 83%~97%）。

`chunk.py reconcile` 只处理**清单项**（bullet list），不碰正文段落 ——
相似度高的正文往往是不同概念，自动统一会制造错误（实测误伤过：
把「底层编排框架」改成「事件驱动框架」）。

## 7. 回填要落在块文件，不要落在成品

术语不一致要改 `NNN.zh.md`，再重新 `join`。直接改合并后的 final 文件，
下一次 join 就会全部丢失。

**非首块必须带锚点**，`bundle` 会自动生成：上一块末尾几句的**原文 + 对应译文**，
用来对齐语气和术语，不用猜上一块翻到哪。

## 8. 分块纪律（违反即本次翻译作废）

在「由同一个执行者扮演全部 agent」的模式下，**隔离必须显式规定** ——
否则执行者天然是全知的，锚点机制永远检验不出来。

1. **不得预读**：翻译第 N 块时，只能看第 N 块内容和上一块的锚点。
   **严禁**读取第 N+1 块及之后的原文，**严禁**读取全篇 md。
   提前知道后文写出来的「连贯」，是作弊 —— 它无法证明锚点本身够用。
2. **每块交给全新的执行者**：每一块由一个独立上下文的执行者完成（新会话 / 新子 agent）。
   它可读的东西只有：`SKILL.md`（入口）、`references/execution-rules.md`、
   `data/glossary.yaml`、`data/examples.md`、本块的翻译包。
   除此之外它对其它块一无所知。
3. **串行推进**：第 N 块译文落盘后，才能用它的末尾生成第 N+1 块的锚点。不许并行。

这套纪律存在的唯一目的：**让「拼接后是否连贯」变成一个可以被证伪的问题。**
不隔离的话，这个流程自始至终只是在验证翻译能力，跟 chunk.py 和锚点没有任何关系。

## 9. 交付前守恒校验

已固化为脚本（不再手工 grep/python）：

```bash
python skills/translate-zh/scripts/chunk.py conservation <源.md> <译.md>
```

对比正文（自动截掉「翻译说明」类附录）的标题/链接/图片/引用/围栏计数 +
`$$` 公式块逐块字节级对比；失败退出码 1。已知合法差异：人工补的双语主标题
（源文缺 H1 时）会 +1 标题 —— 命令只报数不判断合法性，差异要逐条溯源。
实测战绩：抓到整翻版丢 1 个链接。
