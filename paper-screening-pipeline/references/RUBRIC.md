# 论文初筛字段规范（screen_rubric）

> 本文件是闭环里唯一的真值标准。 执行 agent（抽取字段）与评估 agent（评审输出）都引用它。
> 修改本文件需人工批准；评估 agent 只能提出修订建议，修改 agent 不得直接改动它。

## 0. 输入材料与可信度

每次任务会提供一篇论文的：

| 材料 | 来源 | 可信度 |
| --- | --- | --- |
| 标题、摘要 | `metadata.json` | 高（官方元数据） |
| 前 2 页正文 | OCR 结果 `page_content`（含引言、贡献列表） | 中（可能因扫描质量抽空；抽空时用摘要补足并标注） |
| 章节标题 | 全文各页 OCR 的 `#` 行 | 低（常缺失，缺失不视为异常） |

全局规则：

- 只依据给定文本判断，禁止使用论文以外的知识。不许凭标题推测底座模型，不许凭领域常识补全数据规模。
- 字数口径：所有「N~M 字」一律按 汉字个数 + 英文单词个数 计；所有字数条款有 ±4 字容差（2026-09-29 用户批准）。例：`用 LLM 合成指令数据` = 6 字。
- 2026-09-29 两次修订（均人批）：数字串计 1 词；分隔符切词争议由容差消解；JSON 围栏等格式包裹不评审（解析层容错）。
- 摘要中的营销话术（`novel framework` / `SOTA` / `comprehensive study`）不等于事实；需正文佐证，无佐证时按「信息不足」处理。
- 文本内部矛盾时以更具体的陈述为准；仍矛盾则该字段留空。
- 章节标题缺失不影响其他字段判定。

## 1. research_area（研究方向）

- 定义：粗粒度领域标签，回答「这篇论文属于哪个研究方向」。
- 取值：不超过 7 字 的中文标签（字数口径见 §0；2026-10-01 人批：上限由 6 改 7，与正例 `多模态情绪识别` 对齐，消除修订记录自认的矛盾），如 数据合成 / 机器翻译 / 评测基准 / 理论分析 / 安全对齐 / 指令微调 / 检索增强 / 多模态 / 智能体 / 语音对齐 / MOE / 多模态情绪识别。可自创贴切标签。
- 修订记录：2026-09-28 原规定「2~4 字」，与本节正例 `MOE/高效架构`、`多模态情绪识别`（6~7 字）自相矛盾，导致执行端照正例输出超长标签。现放宽为 ≤6 字以对齐正例。2026-10-01 上限由 6 改 7——上一次修订只改了一半，正例 7 字仍与 6 字上限冲突（b025 `acl-srw.6` 触发）。
- 正例：`事实核验`、`MOE/高效架构`、`多模态情绪识别`
- 反例：
  - `多语种长音频语音强制对齐精度不足` ← 这是「问题」，不是方向
  - `用多保真物理证据验证材料声明` ← 这是「方法」，不是方向
- 边界：方向 ≠ 问题 ≠ 方法。三者混淆是最高频错误。
- 正例中的名词化倒装（事实核验、数据合成等）不构成动宾违规；判定看是否含「发现/检测/提升」类动作语义（2026-09-29 人批）。
- 过粗锚点（2026-09-29 人批）：`人工智能`、`自然语言处理` 级别为过粗；`LLM 安全对齐`、`低资源翻译` 级别合适。

## 2. research_question（研究问题）

- 定义：本文针对的痛点 / 缺口 / 任务本身。是后续按问题检索、聚类的主键——不同方法可解决同一问题。
- 取值：一句话（15~30 字），只写问题本身。
- 正例：`LLM 生成内容缺乏可验证的事实核验手段`、`多语种长音频的语音-文本强制对齐精度不足`
- 反例：
  - `用多保真物理证据验证材料声明` ← 写成了方法，违规
  - `本文提出一个新颖框架` ← 既非问题也非空话，无信息
- 判定要点：句中出现「用…方法 / 提出…框架 / 基于…」等动作主语时，基本可判为写成了方法。

## 3. method_summary（方法概述）

- 定义：本文用什么手段解决了上述问题。
- 取值：25~45 字（2026-09-30 人批：原 30~40 与同节反例的 60 字阈值之间留有 45~60 判不出的死区，且本节正例按条款 0 口径只有 23 字、低于原下限），模板「用〈方法〉做〈事〉，〈关键规模/结果〉」。
- 正例：`用 LLM 自动合成指令数据替代人工标注，覆盖 3 个下游任务`
- 反例：
  - `提出一个新颖框架，在多个基准上取得 SOTA` ← 空话，无任何具体名词，违规
  - 超过 45 字的复述性段落 ← 超长，违规（条款 0 的 ±4 容差计入后，实为超过 49 字）
- 「信息不足」判定：若给定文本撑不起一句含具体名词的话（只剩营销话术），照实填 `信息不足`。这是水论文信号，不是抽取失败，禁止为了填满而编造。
- 模板第三槽缺省（2026-10-01 人批，b016 `acl-srw.78` + b022 `findings-acl.1154` 两次复现后裁）：给定文本确实未披露任何规模或结果数字时，第三槽〈关键规模/结果〉**可缺省**，但 method_summary 总字数仍须落在 25~45；禁止为凑模板编造数字（与 §7.1 一致）。

## 4. training_paradigm（训练范式）

- 定义：本文是否训练模型、属于哪类训练。
- 取值：JSON 数组，元素只能取自 `预训练` / `SFT` / `RL` / `不训练`。

| 取值 | 判定标准 | 典型文本信号 |
| --- | --- | --- |
| `预训练` | 从头预训练，或在大规模语料上继续预训练 | `pre-train from scratch`、`continual pretraining on 2T tokens` |
| `SFT` | 在已训练模型上做有监督微调（含蒸馏：教师输出即标注） | `fine-tune`、`supervised fine-tuning`、`instruction tuning`、`distill` |
| `RL` | 强化学习 / 偏好优化 | `RLHF`、`DPO`、`PPO`、`preference optimization`、`reinforcement learning` |
| `不训练` | 正面描述了研究活动（仅推理 / 调 prompt / 纯分析 / 评测 / 数据集或系统构建），**且全文无任何训练动作** —— 判据是训练动作的有无，不是论文属于哪一类 | `inference-only`、`prompting`、`we evaluate`、`we release a dataset` |
| `[]` 空数组 | 给定文本完全看不出训练情况 | — |

- 多选合法：两阶段训练（先 SFT 再 RL）→ `["SFT", "RL"]`。
- 边界：
  - 「训练动作」的外延（2026-09-30 人批，与 b006「独立预测器归 SFT」主张合并裁决；**2026-10-01 人批加两步判定顺序**，收口泛化动词与推定边界条的冲突，实证 b026 `acl-srw.47`、b029 `acl-long.1578`）：训练动作指**对论文所用模型的训练**——预训练 / SFT / RL，判据是该模型是不是论文方法的产物。判定分两步：
    1. **先判训练动作的有无**（看训练对象）：训练对象是论文方法产物（方法就是训练它 / 它是本文提出的模型或组件，如 `we design a predictor that serves as an oracle`、`we train a history-aware router`）→ 有训练动作；训练对象**不是**方法产物（对比基线、被引配方如 `the standard "train a text classifier" recipe`、为分析/探测/评测拟合的辅助分类器与线性探针、为构建数据集而训练的生成式模型）→ 不计本文训练动作。
    2. **再判范式族**：表内典型信号词命中 → 按族归类；只有泛化动词（`train` / `jointly train` 这类）而无任一族典型信号词 → 落 `[]`，**即使训练对象是判别模型也不推 `SFT`**。
    - 「判别模型 → `SFT`」仅适用于该判别模型是**方法产物**且原文写明监督训练的情形（`train a classifier to predict X` 且该分类器即本文贡献）；原文另写明它是在已训练模型上微调时同样计 `SFT`，无预训练 / RL 依据时不叠加其他范式。
    - 为分析、探测、评测目的而拟合的辅助分类器 / 线性探针（`train linear probes`、`Probes trained on deep representations`），论文方法本身不训练模型 → 不计为训练动作，不影响 `不训练` 的判定。
  - 微调一个已训练模型 = `SFT`，不是 `预训练`。
  - 构建数据集、发布基准、搭建系统本身不算训练动作，全文再无其他训练动作时 → `不训练`；此类论文若同时出现训练动作（如 `release models trained on <corpus>`），按该训练动作判范式，不填 `不训练`。
  - 只做评测/分析/综述（全文无任何训练动作）→ `不训练`。
  - `不训练` 与 `[]` 的区分（2026-09-28 新增，2026-09-30 两次人批修订）：`不训练` 是有证据的否定——文本正面描述了研究活动（评测 / 分析 / 综述 / 数据集构建 / 系统搭建）**且全文无任何训练动作**时填 `不训练`。`[]` 用于**两种**情形：① 材料残缺、提不出任何研究活动（如 OCR 只到摘要）；② 文本确有训练动作，但表内任一范式族的典型信号词全缺、范式不可判定（如仅见 `jointly train these components` 这类泛化动词，无从判断是预训练还是微调）。两者的共同点是「按给定文本无法确定范式」，只是一个缺材料、一个缺信号。不得因为「没写训练」就落 `[]`。「提出框架 + 全面评测」「发布数据集」这类正面描述研究活动、且无训练动作的论文填 `不训练`，不是 `[]`。
  - 蒸馏（用教师模型输出训练学生）= `SFT`。
  - 对抗 / 博弈式训练（2026-09-30 人批）：原文明确在**优化一个策略**（`optimize the ... policy`、`learn a policy`）且优化信号由对手或环境**自适应**给出（`alternating adversarial training`、`adversarial game`、self-play）时，计 `RL`——即使全文无 `RLHF` / `DPO` / `PPO` 等词；仅按监督损失交替更新、无策略优化语义的计 `SFT`。两者都判不出时按上一条落 `[]`。
- 反例：`["微调"]`、`["预训练?"]`、`["supervised"]` ← 越界或不确定，违规；不得自造枚举值。
- 推定边界（2026-09-30 人批）：只有表内**已出现某范式族的典型信号词**、仅在该范式的哪个枚举值上存在落点歧义时，才可按最接近的合法值；**表内一个信号词都没有时禁止推定**，按上一条落 `[]`。

## 5. base_model（基础模型）

- 定义：本文方法的底座模型。
- 取值：仅当文本明确写出可指认的模型标识才填，如 `Qwen2.5-7B`、`LLaMA-3-8B`、`GPT-4`、`Mixtral-8x7B`。多个用逗号分隔。
- 禁止（这是脑补重灾区）：
  - `7B VLM`、`7B model`、`our model`、`a VLM` ← 「尺寸 + 类别泛称」不可指认具体型号，留空
  - 凭标题/领域常识推测模型 ← 留空
  - 把评测时对比的模型当成本文底座 ← 留空
- 宿主模型计入（2026-09-29 人批）：方法施加于其上的模型算 base_model，判据是原文明确该模型承接受了本方法（如 we apply X on Y / our defense on Y），而非仅在评测表中与 Y 对比。
- 实验设置句里的模型（2026-09-30 人批）：模型名仅出现在 `Experiments on <benchmark> with <models>` 一类实验设置句，但论文明确自述其方法施加于该类 backbone（如 `ensuring compatibility with Euclidean backbones`、章节标题 `Backbone Generalization`）时，视为宿主 → **填入**；无此自述、模型仅作对比 baseline 或被专门评测 / 审计 / 分析（见下一条）→ 留空。
- 以某模型为**评测 / 审计 / 分析对象** ≠ 方法施加于其上（2026-09-30 人批）：`we evaluate X` / `we test X` / 本文专门研究某类模型的行为，都不是把方法施加到 X 上 → 该模型**留空**；研究对象归 `research_question`（如「评测 GPT-4 的安全性」）。
- 不训练模型、但方法施加于现成模型（2026-09-30 人批，两批复现后补）：`training_paradigm` 取 `不训练` 时 `base_model` **仍可非空**——plug-and-play / 推理时干预 / 检索增强这类方法施加于某现成模型之上，该模型即宿主 → 填入（实测：推理时注入扰动的 `LogicLLaMA`、plug-and-play 检索重排的 `CT2Rep, M3D, RadFM`）。
- **判定顺序（2026-10-01 人批，收口 12 批聚集的方向分裂）**：`base_model` 按以下顺序判，命中即停：
  1. **装载判据**：本文产出物（系统 / 防御 / 扰动 / 重排器 / 路由器等）装在该模型上运行、或原文自述方法作用于该模型（`we apply X on Y` / `our defense on Y`）→ 填；只是拿探针 / 量表 / 攻击去**测量**它 → 不是宿主。
  2. **增益结果句计入施加证据**：模型具名且出现在本文方法改变其输出的结果句中（`<Model> 的 <metric> 从 a 升到 b`、`our method improves X on <Model>`）→ 视为施加自述 → 填入（实证：`findings-acl.1200` 的 `GPT-4o-mini`，`SP@1 从 60.21% 升至 66.70%`）；仅章节标题 / 结果表头罗列（`<Model> under <condition>`）不计（2026-09-30 b023）。
  3. 都不命中 → 按上方各条留空。
- 架构名与泛化后缀（2026-10-01 人批，b026）：裸架构名（`GraphSAGE`、`BERT`）单独出现且原文明确为本文所用模型 → 可指认，可填；带泛化后缀的写法（`GraphSAGE-style` / `X-based` / `X-like`）→ 按泛称处理，留空。
- 对抗攻击 / 越狱 / red-teaming 类论文（2026-10-01 人批，b027）：被攻击的目标模型是**研究对象**而非宿主 → 留空，其身份归 `research_question`（如「评测 LLaMA-3 的越狱鲁棒性」）。
- 正例：`Qwen2.5-7B`、`ColBERT`、`Llama3.1-8B-Instruct`
- 反例：`transformer-based`（泛称，不算具体模型）

## 6. data_scale（数据规模）

- 定义：训练数据量。
- 取值：仅当文本明确写出训练数据的量才填，如 `1M 样本`、`2T tokens`、`260K pages`、`827k tokens`。
- 禁止：
  - `多个数据集`、`several benchmarks` ← 无具体量，留空
  - benchmark/评测集规模不算训练规模（如 `JobSearch-XS 基准` 是评测集，不应填为训练数据规模）——**除非**原文明确本文模型在该 benchmark 的训练切分上训练，此时按训练切分规模计入；原文两处数字矛盾时按 §0「仍矛盾则留空」处理（2026-10-01 人批，b027 同批 2 篇触发）
  - 推理阶段的处理量（如部署 `100M+` 次）← 非训练数据，留空
- 正例：`260K pages`、`MS MARCO 48250 样本对`（若确为训练数据）
- 反例：`大规模语料`（无具体数字）
- 边界（2026-09-30 人批）：
  - 是否留空以 `training_paradigm` 的**实际取值**为准，不按论文类型判定：取值为 `不训练` → 留空（数据集规模、标注题量都不是训练数据量）；取值为其他（含 `[]`），且原文明确模型在该语料上训练（`models trained on X` / `trained on <corpus>`）→ 该语料规模计入。只披露语料总量、未单独披露训练切分时按总量填，保留原文的「约 / approximately」限定。
  - RL 场景：**训练所用的** prompt 集 / rollout 条数**算**（RL 的训练输入就是 prompt 与 rollout）；推理阶段的采样量不算。
  - 范式非 `不训练` 但原文未披露任何训练数据量 → 留空，不编造（2026-10-01 人批，与 §7.1 对齐）。

## 7. 通用禁止事项

1. 禁止编造：任何字段的值必须能在给定文本中找到直接依据。
2. 禁止外部知识：不引用论文以外的信息补全字段。
3. 禁止自造枚举值：`training_paradigm` 只允许 rubric 列出的四个值。
4. 禁止把营销话术当事实：`SOTA` / `novel` / `comprehensive` 需正文佐证。
5. 区分两种「空」：
   - `base_model` / `data_scale` 留空 = 文本没写（正常，不代表论文差）
   - `method_summary` 填 `信息不足` = 文本撑不起实质内容（水论文信号）
   - 两者含义不同，不可互相替代。
6. 关键方向词、对象词与原文相反（如正交补/原空间、增加/减少）时，即使其余描述有据也判违规（2026-09-29 人批）。

## 8. 前置分析（执行端阅读理解层）规范

> 2026-09-28 新增。起因：评估视角 p6_overlap 实测发现前置分析普遍在复述 JSON 结论（6/6 篇），
> 而 rubric 全文无任何条款可约束它，导致违规只能挂靠邻近条款、修订时无可引用依据。
>
> 2026-09-29 第三~五次修订（人批）：经「行模板 → 自然散文 → 高密度笔记」多轮迭代定稿为
> **两层结构**——先「分析」（高密度犀利笔记），后「字段」（逐字段结论 ← 依据），两层不复述彼此。
> 原「4 行 × ≤25 字 / 合计 ≤100 字 / 禁写结论」及全部微规则补丁废除。防编造由「引文逐字可核对」
> 承担，防跑题由「分析层内容服务于字段判断」承担。

执行端在输出字段 JSON 之前先写 markdown「前置分析」，两层结构，先分析后字段：

**第一层·分析**（3~6 条要点）：像科研笔记一样犀利——这篇论文实质在干什么、卖点是什么、
站不站得住、弱点在哪、材料有什么局限。要点式短句，不写连接词废话；提到原文时**逐字引用**
（自然嵌入句中）并注明位置代码。禁止定性空话（「方法很新颖」「内容很丰富」类）。
**至少 1 条必须是犀利点评**（下判断：新在哪 / 弱在哪 / 坑在哪 / 本质是什么）；全条目中性复述判违规。

**第二层·字段**：四个判断型字段逐行「结论 ← 依据」，一行一个：

- 顺序固定：`research_area` / `training_paradigm` / `base_model` / `data_scale`；
- 每行 = 结论 + 一句依据（逐字引文或指向分析层 + 条款 N）；
- 材料无支撑的字段写「（空）← 找过哪里、未命中什么」，不硬编；
- 分析层出现过的证据不整段复述，只指向它。

底线（两层通用）：

- 引文逐字、连续子串、真实存在；跨句/跨列举用 … 显式标出；禁止编造，禁止把多个离散信号词
  拼成一条引文；
- 位置代码唯一词表：`标`=标题 / `摘`=metadata 摘要 / `正`=前 2 页正文 / `贡`=贡献列表 /
  `§n`=第 n 节（rubric 条款一律写「条款 N」，不用 §N）；
- 相关工作中他人方法的描述不得作为本文判据；引用须包含决定判断的信号词本身，不能只引
  数字或名词就下定性结论；
- 字段层四行必须都有着落（有结论或有「（空）← 检索说明」）。
