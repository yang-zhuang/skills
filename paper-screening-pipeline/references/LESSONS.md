# LESSONS — 论文初筛闭环踩坑录

条目格式：现象 → 根因 → 改哪里 → 改成什么。base 指纹见 `scripts/BASE.txt`；
脚本演进后老条目是否仍适用，先对指纹再照抄。

## R1 字数口径自相矛盾（2026-09-29，batch_001~002）

- 现象：同一输出按评审口径一变就在合规/违规间翻转，评估端判定随机摇摆。
- 根因：rubric 同时写了「连续字母数字串计 1 词」与「数字不计」，两句对数字串矛盾。
- 改法：实测临界样本确定影响面 → 统一为一种口径 → 加 ±4 字容差（切词临界差异不讨论）。
- 教训：rubric 每加一条规则，先 grep 有没有与既有条款打架；口径类规则必须有可复算的例句。

## R2 泄露判定条款被三个边界案例反复击穿（2026-09-29，batch_002~005）

- 现象：§8「不得提前泄露结论」在专名引用、跨句拼串、领域名词判据三类场景误伤。
- 改法（逐条进 rubric §8）：专名豁免（引用决定性单一标识串不算泄露，禁罗列互斥候选）；
  引用须为原文连续子串（跨句用 … 标出）；research_area 的引用须含领域信号词。
- 教训：禁令类条款必须同时写豁免边界，否则执行端为避禁令会扭曲取值。

## R3 多视角评审是负资产（2026-09-29，batch_004 vs 005 A/B）

- 现象：每篇 6 视角 × 1 抽取 = 7 次调用，一批 42 次调用 47 分钟。
- 根因：6 个评审员各自重读一遍 rubric + 论文，做了 6 遍 1 遍能做完的事；三轮下来
  剩余问题全是条款歧义，没有一条是「评审员漏看」——隔离没换来质量。
- 改法：单评审员 full 视角一次审完。A/B 同 6 篇对比：47.0 → 12.9 分钟，调用 42 → 12，
  violation 两批同数且新架构多抓 3 条旧架构放过的真错。
- 教训：加隔离前先问「三轮数据里它拦住过什么」；拦不住的隔离是纯成本。

## R4 评审意见必须自包含（2026-09-29）

- 现象：修订 agent 每次都要重读论文全文和 12KB rubric 才能动手。
- 改法：评审输出每条 violation 加 rule_text / current / evidence / suggestion 四字段，
  suggestion 必须是可直接替换的成文措辞。
- 账：评审端每条多抄两段（几十 token），修订端省掉两份全文阅读。

## R5 修改触发要有过滤器（2026-09-29）

- 现象：早期每批评审意见全单照改，rubric 从 12 条长款膨胀到补丁摞补丁。
- 改法：三级分级（见 TRIAGE.md）；聚类计数是唯一判断依据。
- 教训：闭环的产出不是「每次都有修改」，而是「该改的改、不该改的不动」；
  某批没有重复主题就直接跑下一批。

## R6 manifest 必须锁 sha1（2026-09-29，batch_001）

- 现象：batch_001 的 manifest 标 prompt_version=v1，实际跑的不是 v1，无法追溯。
- 改法：`prepare_batch.py` 建批时把 rubric/prompt/review 的 sha1 写进 manifest；
  跨批对比前先对指纹。

## R7 版本号指代失实会复发（2026-09-29，v4 与 v5 各一次）

- 现象：修订 agent 产出的 prompt 里出现「以上三类判定已在第一部分完成」，
  而三类检查就发生在本段——v4 修过一次，v5 复发。
- 改法：修订产出必须由主 agent 复核指代类表述（「第一部分/上面/如前所述」逐个核对指向），
  契约校验脚本查不出这类问题。
- 教训：修订 agent 的验收 = 机器契约校验 + 人工指代复核，缺一不可。

## R8 主 agent 不搬运全文（贯穿全程）

- 现象：多批迭代时若把评审 JSON 全文读进主上下文，上下文随批数线性膨胀。
- 改法：子 agent 交接只带回报摘要（路径 + 字节数 + 条数）；明细靠文件路径按需读。

## R9 评审把 rubric 措辞当论文证据（2026-09-30，batch_011 重发时抓到）

- 现象：`evidence` 写的是条款 4 的措辞「仅推理 / 只做评测 / 只发布数据集或系统」，
  该串在 RUBRIC.md / EXTRACT.md 里有、在本篇 inputs 里 0 次。
- 抓法：`cluster_reviews.py` 的引用核验（evidence「」引文 ⊆ inputs）——旧的人工核验漏过。
- 改法：重发评审 agent 时在派工话术里点明「evidence 必须是第 3 个文件（论文输入）里逐字存在的
  片段，条款原文放 rule_text」。单发不改 EVALUATION.md（它已写「论文原文的逐字引用作证据」）。

## R10 跨批复现会被「同字段同条款」的假家族骗（2026-09-30，条款 4 实测）

- 现象：`training_paradigm` + 条款 4 跨 4 批（b002/003/007/011）看似「跨批复现 → 立即修改」，
  逐批对读发现方向相反——b003 要求「应填 `不训练`」，b007/b011 要求「应填 `[]`」。
  同条款下方向相反 = rubric 歧义，不是同一家族。
- 抓法：跨批输出必须带**每批的建议摘要**、逐批对读；对齐键用条款而非 kind
  （kind 兜底值「其他」曾把条款 8「引文引错层」与条款 7「编造方向词」并成一个家族）。
- 教训：跨批计数只是「立即修改」级**候选**，家族判定要人看方向；方向冲突时出口是
  SKILL.md §七 终止条件 2「停下交人裁」，不是派修改 agent 去改执行文档。

## R11 新边界条款会与原容错句合谋出新空档（2026-09-30，batch_015 回归）

- 现象：为收口条款 4 的 `不训练` / `[]` 分裂，边界句改成「正面描述研究活动**且**全文无训练动作
  → `不训练`；材料残缺 → `[]`」。回归时 `acl-long.489` 落在第三态——**有训练动作
  （`jointly train`）但无任何范式信号词**：不是 `不训练`（确有训练动作），也不是 `[]`
  （提得出研究活动）。同节**未动**的容错句「不确定时按最接近的合法值」把执行端推向 `SFT`，
  评审要它落 `[]`，而 `[]` 的新定义排除了它。
- 教训：改一条边界句之前，先把同节里所有「兜底 / 容错 / 特殊情况」句读一遍——新边界与新容错句
  的合取很容易造出原条款没覆盖的第三态，而第三态会立刻变成下一个悬案。

## R12 改标准后的验证必须两段都重跑（2026-09-30，batch_015 回归）

- 现象：曾打算只重跑评审（拿新 rubric 喂旧 `fields.json`）来验裁决。错——新标准下
  「应该改填什么」本身会变：`acl-srw.54` 旧输出 `[]`，在新边界句下**仍是 violation**，
  只是应改值变成 `不训练`。只重跑评审看不到执行端是否真的吸收了新边界。
- 做法：`prepare_batch.py --papers` 定向回归，执行端与评审端都重跑；判读标准开跑前写死
  （哪几篇预期转 pass、哪几篇预期仍 violation、哪几篇不受影响），跑完再找理由等于自证。

## R13 改标准只改复述点的一处 = 条款间口径分裂（2026-09-30，batch_017 抓到）

- 现象：上一轮把条款 4 的 `不训练` 判据从「论文类型」改成「训练动作有无」，但同一条规则在
  RUBRIC §4 表格 / §4 两条边界 / §6 边界、EXTRACT 表格两行共五处复述，只改了 §4 一处。下一批
  随即撞上 `findings-acl.1395`——属数据集构建类**且**有训练动作：§4 的动作判据落 `[]`、§6 的
  类型判据要求留空，同一篇论文两个结论。
- 根因：判据维度变了（类型 → 动作），复述点没跟上；§6 那条边界一句里塞了取值（`不训练` 类）
  和类型清单（数据集构建）两种读法。
- 改法：改标准前先 grep 该规则的关键词，把所有复述点（rubric 各节 + 三份作业文档的表格与示例）
  列成清单一次改完；改完再 grep 一遍确认无残留旧口径。
- 教训：条款之间是链（§6 的判据依赖 §4 的取值），只改上游或只改下游都等于没改。R11 是同节内
  新旧句合谋出第三态，本条是跨节、跨文档不同步。

## R14 在含相对指代的清单里插入条目，会打断既有指向（2026-09-30，本轮裁决三）

- 现象：给 §5 补「`不训练` 时 `base_model` 仍可非空」这条时，插在「实验设置句里的模型」与
  「以某模型为评测 / 审计 / 分析对象」之间——但前者末尾有「（见下一条）」正指后者，插入后指向
  被隔断，变成了指向刚插入的新条目。
- 改法：插入前 grep 该清单里所有相对指代（「见下一条」「如上」「本条」），确认插入点不在
  指代的两端之间；或直接插到指代链的末端。
- 教训：R11 是同节内容层面合谋出第三态，R13 是跨节、跨文档不同步，本条是排版层面的指代失效——
  三者都不改语义，但都会让读者按错误条款办事。

## R15 随机抽样会公平地饿死低频类型，测了 21 批没测到一篇综述（2026-10-01）

- 现象：用户问「综述、纯理论、机制、实验、应用型、非标准论文都测过没有」。把全池按内容类型
  分桶后核历史覆盖，各类型覆盖率其实都在 3.4%~5.0%——与池内占比无关，随机抽样是公平的。
  但公平地摊薄就是问题：70 篇分给 8 型，survey 池内只有 21 篇（1.3%），期望不到 1 篇，
  实测 **0 篇**。而「综述 → `不训练`」是条款 4 白纸黑字写着的边界，从没被实证过。
- 改法：加 `classify_papers.py`（纯规则，不调 LLM，只用 venue + 标题 + 摘要 + 章节标题）把全池
  分成 8 型，`prepare_batch.py` 加 `--strata N` 按型给固定配额，manifest 记 `type_quota` 与
  `paper_types`——跨批对账可按类型看覆盖，不只按篇数。
- 分层后的首轮结果（batch_021~024，28 篇）：**survey 4/4 干净**，条款 4 的综述边界首次拿到实证；
  真薄弱点是 **nonstandard**（thesis proposal / tutorial），5 篇里 1 篇 violation、2 篇报歧义——
  这类文本里方法常被写成「将要做什么」，模型名常以泛称或被引工作出现，执行端容易把
  「相关工作的模型」误当宿主（`acl-srw.120` 填了 `HRM, TRM`）。
- 教训：样本量够不等于覆盖够。**按总篇数衡量测试量会掩盖类型空洞**，得先有分桶才能谈覆盖。
  验证报告见 `references/coverage_20261001_types.md`。

  §5 需要一条针对 proposal 类文本的模型名判定规则。详见 `references/coverage_20261001_types.md`。
- **人裁改一条条款时，必须连带裁掉与之给出相反落点的另一条（2026-10-01 实测）**：上一轮把
  「判别模型/预测器 `train a classifier`」并入 §4 的 SFT 外延，却没动推定边界条「表内一个信号词
  都没有时禁止推定 → `[]`」。同一句原文两条规则给出 `SFT` 与 `[]` 两个答案，下一批即以 violation
  形式返回（batch_026 的 `acl-srw.47`）。裁决清单里应固定一问：**除本条款外，还有哪条规则会对
  同一输入给出不同落点？**
- **修订记录里写着「自相矛盾」的条款说明只改了一半**：§1 修订记录自陈「原规定 2~4 字与正例
  （6~7 字）自相矛盾」，改后上限定 6 字、正例仍留 7 字的 `多模态情绪识别`（batch_025 的
  `acl-srw.6` 触发）。人裁落地后要回头核：正例、反例、上限阈值是否都跟新口径对齐。
- **「测过且干净」不等于「这类论文没问题」（2026-10-01 实测）**：method 型前 3 篇零违规，
  加量到 6 篇立刻冒出 2 条 violation（33%，`acl-long.1578` / `findings-acl.1200`）。
  判断某个类型是否安全，看的是**测过多少篇**而不是**出过几次违规**——6 篇以下的类型结论
  都还只是抽样噪声。类型表里的篇数列比 violation 列更该看。
- **空值 violation 无法逐字核验（2026-10-01 修）**：判「某字段不该留空」时 `current` 原值就是
  空字符串，`current ⊆ fields.json` 的核验必然失败（`findings-acl.1200` 连挂两次）。
  改为按字段名核验：`current` 留空但**必须给 `field`**，脚本核对 `fields.json` 里该字段确为空
  （`""` / `[]`）。契约同步在 `EVALUATION.md`，逻辑同步在 `cluster_reviews.py`。
- **跨批口径无单一真源（2026-09-30 实测）**：命中条件实际是「本批有 + 历史 ≥1」——本批不复现
  就报空（batch_013 报无跨批复现，而 batch_011 报 §4 命中 6 批，读的是同一段历史）；结论取决于
  「最后一次重算的是哪一批」。另 `n_batches` = 历史命中 + 本批（脚本先跳过本批，再把本批显式追加
  一行供逐批对读），读「N 批」时要知道其中 1 批是本次。已升级未裁事项没有机器挂账，只靠人写的
  ruling 文件。
