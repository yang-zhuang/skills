## 裁决一：条款 3 字数界限自相矛盾 → 取值改 25~45 字

**问题**（b003 + b019）。条款 3 取值写「30~40 字」，条款 0 给 ±4 容差 → 上限 44；同节反例却写「超过 60 字」违规。45~60 落在死区，判不出。旁证：条款 3 自己的正例按条款 0 口径只有 23 字，低于原下限 30 —— 30~40 从未被当硬界限执行。

**裁决**：取值改 **25~45 字**；反例阈值 60 → 45（条款 0 的 ±4 容差计入后实为超过 49 字）。

**为什么不选另一方案**（保留 30~40、反例改 44）：那要一并改写条款 3 自己的正例（23 字），等于承认正例是错的；且 30~40 档本身偏窄，实测执行端普遍写 30~50。选 25~45 后，原正例合规、`acl-short.66` 的 52 字违规、三处口径一致。

**落点**：RUBRIC §3 取值行 + 反例行；EXTRACT 字数口径段 + 高频错误表 `method_summary` 行。

## 裁决二：条款 4「训练动作」外延未定义 → 与 b006 合并裁，分界落在「方法产物」

**问题**（b006 + b008 + b019）。条款 4 的 `不训练` 行要求「全文无任何训练动作」，但「训练动作」从未定义。`acl-short.66` 的 `train linear probes` 算不算，决定落 `不训练` 还是 `[]`，并级联条款 6。同时 b006（`acl-long.392`，预测器 `serves as an oracle`）主张「训练独立的预测器 → 归 `SFT`」—— 与「探针不计入」方向相反。两条必须一起裁，否则裁一边就把矛盾推给另一边。

**裁决**：训练动作指**对论文所用模型的训练**（预训练 / SFT / RL），判据是该模型**是不是论文方法的产物**：

- 论文的方法就是训练一个判别模型 / 预测器 / 回归头（`we design a predictor that serves as an oracle`、`train a classifier`）→ 计 `SFT`；
- 为分析 / 探测 / 评测拟合的探针 / 辅助分类器（`train linear probes`、`Probes trained on deep representations`）→ **不计**为训练动作。

**为什么是这条分界**：b006 的预测器是方法的组件（引导主流程的 oracle），b019 的探针是分析工具 —— 两者的差别不在「是否用了 train 这个词」，而在该模型在论文里的角色。用「是不是方法产物」一刀切，两侧都能判。

**落点**：RUBRIC §4 边界组新增一条（含两个子项）；EXTRACT 两处复述（`## 第二部分` 的 `training_paradigm` 说明条目 + 高频错误表该行）。

## 裁决三：条款 4 × 条款 5 组合边界 → `不训练` 时 `base_model` 仍可非空

**问题**（b017 / `findings-acl.1213` + b019 / `acl-long.1411`，两篇）。两篇都是 `不训练` + `base_model` 非空（推理时注入扰动的 `LogicLLaMA`、plug-and-play 检索重排的 `CT2Rep, M3D, RadFM`）。两次执行端都填、两次评审都放过 —— 已形成一致做法，但 rubric 无条款依据，属于「做法对、标准缺」。

**裁决**：条款 5 补「`training_paradigm` 取 `不训练` 时 `base_model` 仍可非空 —— plug-and-play / 推理时干预 / 检索增强这类方法施加于某现成模型之上，该模型即宿主 → 填入」。

**落点**：RUBRIC §5 新增一条（放在「实验设置句里的模型」与「评测 / 审计 / 分析对象」之间，保持「见下一条」的指代指向正确）；EXTRACT 高频错误表 `base_model` 行。
