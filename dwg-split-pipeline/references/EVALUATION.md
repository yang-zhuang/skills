# 评估标准：怎么算「拆成完成」

评估 agent 必读。主 agent 也读它来决定要不要派下一轮。

## 总原则：两条腿，各干各的

拆得对不对，一半能**算**，一半只能**看**。

| 谁 | 判什么 | 特点 |
|---|---|---|
| `verify_split.py`（脚本） | 实体数守恒、产物齐全、图面非全白、单图性的几何指标 | 零 LLM、可复现、免费 |
| 评估 agent（视觉） | 这一张是不是完整的图、图框有没有被切、图名对不对 | 只能看，不可复现 |

**为什么必须分**：视觉判断不稳定 —— 同一张图两轮可能给不同结论，边界情况尤其飘。
所以凡是能算准的，**不要**交给模型去"看"。脚本摘掉一大半之后，视觉 agent 只回答
下面 V1~V6，结论才稳。

**先跑脚本再派视觉**，顺序不要反：脚本已经报出来的问题，视觉 agent 不必再花 token 找。

## 第一层：确定性判据（脚本自动跑，不用管）

跑 `python verify_split.py <拆分输出> <源图> --out=../04_verify` 即可，输出
`04_verify/校验报告.json`。里面的 `verdict` 已经是结论：

| 编号 | 判据 | 级别 | 说明 |
|---|---|---|---|
| E0 | **源图可读性** | error | 源图里有 `ACAD_PROXY_ENTITY`（天正对象）→ 直接 revise：其几何只有天正能解析（显示缓存是空壳、对象真身是天正私有二进制），产物**必然缺这些内容**，后续所有校验只对得上「Python 可读实体」。要完整产物：在天正里炸开（EXPLODE，可能要两次）后另存 DWG 再重跑。**没有 E0 时残图会假 PASS**（2026-09-23 实战踩过：811 实体的天正图，产物只剩 193 个，旧评分照样 PASS） |
| E1 | **实体数守恒** | error | `Σ各簇 + 残片 == 源图里能求出 bbox 的实体数`。注意是"能求出 bbox 的"——求不出 bbox 的实体本就不参与聚类（`split_dwg.py:263-265`），拿 `len(modelspace)` 直接比会误报 |
| E2 | 产物齐全 | error | 每个序号目录里 dxf + json 都在，该有的配色 PNG（白底黑白、黑底彩色）一张不缺 |
| E3 | PNG 非全白 | error | 非白像素占比 < 0.1% 或体积 < 5KB → 文件在、内容是白纸，渲染其实失败了 |
| E4 | 图名口径自洽 | error | 「图名文本非空」必须与「图名实体数 > 0」同时成立（README 明文规定这是不该出现的组合），否则 `--title-mode` 静默失效 |
| E5 | 字体解析探针 | error | 在用文字样式的字体被解析成 TrueType 替身（应解析为 SHX 描边字体）→ 加粗失效、轴号/尺寸数字发虚。修 `.env` 的 `SHX_FONT_DIRS`（`check_env.py` 会点名缺哪个）。这是文字发虚问题里**能算的那一半**，渲染前就拦下 |
| W1 | 单图性 | warn | 对拆出的每个产物重跑一次连通聚类，分量数应为 1。> 1 时报「最大间隙 / 图对角线」比值，**交视觉终判**（见下节） |
| W2 | 巨簇 | warn | 单簇实体数 > 5000：`margin` 切不开的典型症状 |
| W3 | 碎簇 | warn | 1~2 个实体的簇，多半是没并进图框的碎渣 |
| W4 | 残片占比 | warn | 不出图的文字残片占源图实体数 > 5% |

**error → 直接 revise，不必派视觉**。**warn → 必须派视觉确认**。

## 第二层：视觉判据（评估 agent 回答这 7 条）

每条都要**看图后**才能答。图片位置固定，不要搜索：

| 要看什么 | 路径 |
|---|---|
| 拆分前的整张图 | `02_overview/<源图主干>_整图_白底黑白.png`（另有黑底彩色） |
| 拆分后的每一张 | `03_split/<序号>/<图名>_白底黑白.png` |
| 脚本已经报出的问题 | `04_verify/校验报告.json` |

| 编号 | 判据 | 失败的样子 |
|---|---|---|
| V1 | **一个序号目录里只有一张完整的图** | 里面挤着两张平面的各一半；或者只有一根轴网、没有图形 |
| V2 | **图框与标题栏没被切到隔壁** | 甲图的标题栏出现在乙图的目录里；图框缺一条边 |
| V3 | **轴网下方不该有图名大字** | 图形被一行很大的字压在下面、整个图幅被撑变形（`--title-mode=auto` 应已剔除） |
| V4 | **不该有两块明显分离的子图** | 一张图里上半张是平面、下半张是另一张平面，中间大片空白（对照 W1 报的间隙占比） |
| V5 | **图名与图面内容对得上** | 文件叫「二层平面布置图」，图里画的却是楼梯大样 |
| V6 | **没有整张图丢失或多出** | 整图里数得出 7 块，`03_split/` 只有 6 个目录 |
| V7 | **文字与数字笔画黑实、放大可读** | 轴号 ①②/尺寸数字发灰、细成发丝，而同图**中文却清晰** —— 这是字体分支问题（E5 的像素层后果），调分辨率治不好，修 `.env` 的 `SHX_FONT_DIRS`。V7 还兜住 E5 探针管不到的：字形缓存污染导致的空心/放大、加粗未生效、低分辨率发丝 |

### V3 的补充：什么算"图名大字"

轴网正下方那一行、字号明显大于图内其他文字的字（实测「城市疏捞队门卫室」字高 7234，
把包围盒横向撑到 2.70 倍）。`verify_split.py` 的 E4 只校验口径自洽，**字还在不在图上，
得看图**。注意 **指北针的「北」不算图名**，必须保留（程序里有 `_TITLE_STOPWORDS` 保险）。

## 「明显分离」怎么量化

脚本算三个量：拆出图的**连通分量数 N**、**最大分量间隙 G**、**该图对角线 D**，
报出 `G/D` 比值（`校验报告.json` 里 `multi_component` 那条的 `gap_ratio`）。

判定口径 —— **脚本只报警，视觉终判**：

- `G/D > 5%` → 脚本报 warn，视觉必须回答 V4；
- `G/D ≤ 5%` → 脚本不报，可视为图内正常留白。

**为什么不干脆让脚本判死**：图例块、指北针、独立的标准层标注，本来就离主体很远，
一刀切会把正常图判成错的。阈值在 `verify_split.py` 的 `SEP_RATIO_WARN`，要改就改那里，
**不要在评估里临时改口径** —— 口径飘了，两轮的结论就没法比。

## 视觉意见的格式（必须照这个写）

写到 `05_review/视觉意见.json`：

```json
{
  "job": "<源图主干>",
  "round": 1,
  "verdict": "pass",
  "issues": [
    {
      "id": "V4",
      "level": "error",
      "target": "03_split/02/二层平面布置图.dxf",
      "claim": "图的下半部分有一块与主体不相连的独立线段，占据了整图 13.6% 的间距",
      "evidence": "对照 02_overview/ 的整图，该位置属于另一张图的残留",
      "suggest": "疑似图名下划线未随图名一起剔除，检查 title_ents 的收集范围"
    }
  ],
  "passed": ["V1", "V2", "V5", "V6"]
}
```

字段要求：

- `claim` **必须可证伪** —— 写出位置、数量、和什么对比得出的。"切得不太好"是无效结论。
- `evidence` 必须指向**看过的具体文件**，不能是"根据经验判断"。
- `passed` 要列出**确认没问题的项**，否则主 agent 无法区分"没查"和"查过没事"。
- 已经判定修复的问题**不要重复提**，除非这轮能复现 —— 每轮都会把历史结论给你。

## 判定与闭环

| 情况 | 动作 |
|---|---|
| 脚本有 error | 直接 revise，不派视觉（省钱） |
| 脚本只有 warn + 视觉全 pass | 收敛 |
| 视觉有 error | 派修改 agent；改完从「拆分」重跑（第 2 步），不必重渲整图 |
| 到 3 轮仍不 pass | 停，标 `stuck` 交人 |
| 问题集合连续两轮无变化 | 停，标 `stuck` —— 修改 agent 改不动了，再转只是烧 token |

## 常见误报（视觉 agent 注意）

| 看着像问题 | 其实正常 |
|---|---|
| 指北针离轴网很远 | 它本来就在图幅边上（V4 别拿它当"两块分离"） |
| 图例块独立成块 | 总平面图里很正常 |
| 拆出的图很小、只有几个实体 | 可能是倾斜观测的小图（实测 32 个实体就是一张正常图） |
| 某个序号目录是 `05/05.dxf`（用序号命名） | 说明没识别到可信图名，是**有意的**宁缺毋滥，不是 bug |
| 产物里只有 `split_report.json`、0 张图 | 空图源（12,991 字节的空壳），不是失败 |
