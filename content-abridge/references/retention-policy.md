# 保留策略（编辑方针）

版本：v6.4（2026-10-06）
地位：三个 agent 判断"删 / 留 / 简化"的**唯一事实来源**。修改本文件必须走 DESIGN.md §5 的演化流程（用户反馈直接改 / defer 频次聚合人工确认后改），每次修改追加文末变更记录并升版本号。

## 0. 通用铁律（所有类型适用）

1. **不添加**：缩编稿里只允许出现原文作者的内容。不解释、不点评、不总结升华、不补背景知识。
2. **如实**：数值、结论、代码、命令、提示词，要么一字不改地保留，要么整块删除。禁止"概括性转述"数值或结论。**直接引语逐字保留**（v6.4）：含原文字符形态——原文用弯引号/弯撇号（“ ” ‘ ’）就照抄弯引号，不得"规范化"成半角直引号；引号字形是引语原文的一部分（起因：@20261005-htba-short 提示词样例三行被转成直引号，评审 defer）。
3. **自包含**：读者不看原文，也能明白要解决的问题、作者的贡献是什么。
4. **拿不准时的默认规则**：属于"作者自己的核心内容"→ 留；属于"别人的内容或服务性铺垫"→ 删。
5. **输出语言一律中文**（v2）：原文为其他语言时，缩编即翻译式压缩。代码、命令、提示词原文、专有名词、模型名、直接引语可保留英文；数字一律原样。
6. **信息密度**（v3，v5 强化）：每个保留段落必须承载不可再删的有效信息。重复表述、修辞铺陈、过渡衔接、礼貌性套话直接删除；同一论点在引言与正文重复出现时只保留一处（通常保正文）。**"完整保留=信息完整，不是逐字照抄"是通用规则，适用于一切类型分节**（v5 自 paper 细则上提为铁律）——分节三栏表里"完整保留"档的内容，同样允许压缩措辞、重组结构、删冗余叙述，只要要素一个不丢。
7. **结构与风格可为可读性让路**（v4）：表达顺序、标题层级、段落划分、句式风格、格式（列表化/表格化）都可以修改，目标是更直观、阅读更顺、逻辑与层级感更强。两条前提：(a) 核心内容不得过度删减（铁律 6 的信息要素一个不少）；(b) 原文中的**示例阐述属于作者核心内容，必须保留**——示例是论证的一部分，不是修饰。铁律 2 的一字不改范围（数值/代码/命令/提示词/直接引语）不因本条放宽。
8. **列举型内容优先结构化呈现**（v5，v6 补判定线）：多项并列的特征、机制清单、对比项优先改写为结构化形式——表格、列表、条目、SVG 图示等均可，以**对该内容最直观的一种**呈现，不以叙述段落铺开。形式选择只看可读性，不限于表格。判定线如下：

| 原文的"形状" | 该用什么 | 典型情形 |
|---|---|---|
| **有"列"**：≥3 个并列项且每项带 ≥2 个相同属性；双面对比；术语/映射关系 | **表格** | 多框架逐维对比、价值点+说明+支持情况、命令→作用映射 |
| **有"方向"**：顺序流程/分支决策、层级包含、循环反馈、光谱轴上的位置 | **SVG / 列表式结构化** | agent loop 回路、组件嵌套、"可预测性—自主性"光谱、状态转换 |
| **只有"逻辑"**：因果论证链、让步与限定语、≤2 项或属性各异的内容 | **保持叙述**（不强制结构化） | 作者的推理推进、"虽然 A 但仅在 B 条件下"、两项对比 |

一条总则：**形式服务于无损，不服务于好看**。结构化不得牺牲三类东西——连接逻辑（因果/让步）、细微限定语、原文已有的图与表格（原文有图一律保留原图，禁止重绘）。数值/代码/命令/直接引语的一字不改要求（铁律 2）不因形式变化而放宽。
9. **背景/铺垫/概念与工具介绍归"简化保留"档**（v5）：如"什么是 X""为什么这很难"类内容，无论在原文占多大篇幅，都不是作者的核心贡献，只保留理解核心论述所需的最小集（通常一到两段），超出部分直接删。
10. **保留下来的外部内容必须留下出处线索（引用可追溯）**（v6.2）：只要稿件保留的内容**其归属不是本文作者自己**（他人方法、他人的结论/数据集/代码仓库/工具、取自他文的图片），并且**原文在该处或邻近给出了链接**，就必须在两处同时留下线索：

    - **正文**：该内容首次出现处加编号标 `[n]`（同一来源全篇复用同一编号；并列写 `[2][3]`）；
    - **文末**：`## 参考资料` 节按编号列出，每条形如 `- [n] 名称 <原文链接>`。

    做这件事的两个目的（用户@20261004）：(a) 读者一眼看出论断有依据，更信服；(b) 读到不懂处可以跳出去读原文相关材料，读完再回来接着看——参考资料是给读者留的"岔路口"，不是装饰。
    七条边界（缺一不可）：

    - **URL 必须逐字节来自原文**：不得自造、不得换成搜索页/站内页、不得补 DOI。任务包里 `input/refs-candidates.json`（打包时由 `extract_refs.py` 自动生成）是唯一可取用来源；自造链接由 `verify_citations.py` 拦截。
    - **编号按 URL 计，不按名称**（v6.4）：同一来源（如 LangSmith）在原文出现两次、URL 不同（一个子页、一个根域）→ **各占一个编号**；只有 URL 完全相同才共用编号。名称重复不合并编号（起因：@20261005-htba-short，评审 defer 无所适从）。
    - **名称不得改写**：取原文该链接的可见文字或原文对该来源的称呼，不得改成宣传语、不得自己起名。
    - **原文没给链接就不编号**：只提到名字没给链接的来源，只留名字，不编号、不进资料节——**不许替作者去补链接**。
    - **删掉的内容，其来源不进表**：参考资料只服务"留下来的内容"，不是原文参考文献的全表。
    - **不得添加原文没有的"延伸阅读"**：任何推荐性质的额外链接都属铁律 1 的"添加"。
    - **图片来源**（原文写作 "Image source: xxx" 之类）按原文语气保留在图注/alt 里；是否并入编号由稿件整体一致性决定，并入时同样只能在原文链接范围内取材。**引用标记本身挂在图片引用之后（`![](path)[n]`），不写进 alt 内部**——alt 是给读屏软件和不显示图片时的替代文本（B3），塞编号既成噪声，也会让部分 markdown 解析器不再把它识别为图片（本机 `@20261003-agents` 补录时 11 张图因此被判成"未被引用"）。

    本条与"删他人观点"不冲突：**删的是内容，不是出处**——正因为留下了别人的东西，才更要标明它来自谁。本条也不违反铁律 1：新增物只有"编号 + 原文已有的 URL 在文末的一处落点"，没有任何解释、评价或额外信息。

## 1. paper（学术文章）

### 类型判定特征

出现以下多数特征即判为 paper：摘要/Abstract、关键词、编号章节（§3.2 / 4.1 式）、参考文献列表、图表编号（Figure 1 / Table 2）、算法伪代码块。

### 三栏表

| 处理方式 | 内容 |
|---|---|
| 完整保留 | 方法部分全部：方法描述原文、方法图、算法流程/伪代码、公式、提示词原文 |
| 简化保留 | 背景 + 要解决的问题（判断标准：读者能回答"作者要解决什么问题、为什么值得解决"）；实验/消融（只如实陈述"做了什么实验、结果是什么"，删论证性铺垫、凑字数的对比讨论）；结论 |
| 直接删除 | 相关工作、讨论、致谢、与引言重复的铺垫 |

### 判断细则

- **"完整保留"的准确含义是信息完整，不是逐字照抄**（v2）：方法部分的叙述性文字允许压缩措辞、重组结构，但设置要素（实验对象、条件设计、每个条件的意图、机制、关键数字）一个不能丢。判断标准：读者能根据缩编稿复述出实验/方法设计。对实验设计类文章（方法即实验设计），此条尤其重要——禁止整段照搬叙述性 setup 文字。
- **图的归属**（起草/评估都用这条）：图/表展示方法、架构、流程 → 方法核心，保留；展示实验结果曲线/对比 → 归实验部分，随实验简化规则处理；纯概念示意 → 倾向保留。三个 agent 本身可多模态直接看图，**必须打开图片判断归属，不得只凭图注文字**。
- **实验简化**的判断标准：删掉的只能是"证明作者方法好"的反复论证；实验设置的关键参数、最终数字必须如实保留。分析类小节（further analyses 等）压缩为"一句结论 + 关键数字"，删实验过程叙述。

## 2. blog（观点类）

### 类型判定特征

无学术格式；第一人称观点表达；围绕某议题的论述；可能引用他人言论或新闻。

### 三栏表

| 处理方式 | 内容 |
|---|---|
| 完整保留 | 作者自己的观点、论述、例子、亲身经历 |
| 简化保留 | 必要上下文（一两句，保证论述不断裂） |
| 直接删除 | 引用的他人观点、新闻转述、铺垫、寒暄 |

### 判断细则

- **他人观点引用**：即使作者的论述依赖它，也删。若删后论述明显断裂，允许加一句中性引导语（如"针对 XX 的观点"），但**不得转述他人观点的具体内容**。
- **背景与工具/框架介绍**（v5）：blog 里"什么是 agent / 什么是 X 框架"等教学性铺垫按铁律 9 处理——只留理解观点的最小量，且与引言不重复。
- **对作者零评价**：评估意见里出现"作者说得好/不好"性质的表述，属于 no-fix 噪声。
- 判断标准：缩编稿读完，读者能完整复述**作者本人**的观点链条。

## 3. 教程 / 经验分享

### 类型判定特征

步骤化指令、代码块、命令行、版本号、环境配置、"首先/然后"式行文。

### 三栏表

| 处理方式 | 内容 |
|---|---|
| 完整保留 | 操作步骤、代码块、命令、环境/版本信息、作者踩坑与注意事项（一字不改）；**原文图表**（v6.4，归属判断同 §1 细则——教程的方法总览图/对照表属核心） |
| 简化保留 | 原理性解释（压缩到原长 1/3 以内，且不得改变技术含义） |
| 直接删除 | 宣传性内容、与操作无关的闲聊、开场白；**结论/收尾段**（v6.4：与正文或步骤重复的总结性重复，依铁律 6——非重复的收尾另按铁律 1 判） |

### 判断细则

- 代码块/命令**禁止任何改写**（包括"优化"格式），这类内容的忠实性要求高于 paper 的方法描述。
- 踩坑记录属于作者核心经验，不是闲聊，**必须保留**。

## 4. 跨类型边界条款（v6）

四轮运行中反复出现、但类型分节无法单独规定的边界问题，统一在此规定，适用于所有类型。

### B1 商业/自家产品的提及（区分"操作性用法"与"纯宣传"）

判定动词：**读者能否照着做**。
- **保留**：工具叫什么、怎么装/怎么配、用来干什么、有什么坑——即使它是商业产品。安装命令、配置项、调用方式属操作性内容。
- **删除**：只有价值宣称没有操作信息的部分（"一键部署""立即注册""大幅提升效果"、带推广参数的链接）。
- **整句混合时**（一句里既有操作又有宣传）：保留操作部分，删宣传部分；**禁止因句子带推广链接就整句删除**（over-deletion 是已发生过真实的 must-fix）。
- **与铁律 10 的优先级**（v6.4，答复 @20261005-htba-short E-005）：B1 说删"带推广参数的链接"，铁律 10 说 URL 逐字节保留——**铁律 10 优先**。B1 删的是推广性**叙述文字**，不是 URL 字符本身；一旦该 URL 被正文 `[n]` 引用采用（承载了保留内容的出处），其字符（含 `?ref=` 等推广参数）逐字节保留。
- **事实性功能描述不属"纯宣传"**（v6.4）："支持一键部署""支持 X 格式"这类**可验证的产品能力陈述**随操作性介绍保留，不是 B1 要删的价值宣称（"大幅提升效果""业界领先"才是）。判定信号：这句话能不能在产品文档里被证实。

### B2 他人表述（区分"作者采纳为骨架"与"被引用来评论"）

- **保留**：作者明确采纳、作为自身论述骨架的他人表述（如作者直接采用某家的 workflow/agent 定义作为分类基础）。要求：**以作者的话承接**（"作者采用 X 的区分……"）且不展开他人的论证过程。
- **删除**：作者引用来评论、赞成或反驳的他人观点内容；删后可用一句中性引导语承接（"针对 X 的观点"），不得转述其内容。
- 判断信号：删掉后**作者自己的论述会不会断**——断 = 骨架（留）；不断 = 引用（删）。

### B2.1 对比场景中的"他人"（表格化与删他人观点的交汇处）

作者常把自己的方法与他人的并列对比（"本文 vs X vs Y"），这与"删他人观点"并不冲突——按三级拆分处理，判断信号仍是 B2 的"删后作者论述断不断"：

- **保留（事实性定位）**：他人方法在作者对比坐标系中的**客观存在项**——名称、类别、有无某能力、原文给出的性能数字。删掉它们作者的比较就不成立（论述断），故随作者的对比一起保留；铁律 8 允许将其结构化为表格行。
- **删除（他人的说法）**：他人的**论证、评价、营销话术**——他人自己声称的优势理由、理念阐述、"为什么我们更好"。这些才是 B2 要删的"他人观点"，**不得为了填满表格单元格而把它们塞回来**。
- **全保（作者的比较判断）**：作者对他人的比较结论与倾向（"作者认为 X 强在哪/弱在哪"）是作者自己的内容，一字不失；铁律 1 禁止的是**缩编者**添加评价，不是删改**作者**的评价。
- 单元格内容超范围时的处理：宁可留空或写"见原文"，不得用他人的自述文案补位。

### B3 图片 alt / 图注的书写边界

原文图片常无 alt 或 alt 为空，允许起草补写，但：
- **只能依据图面可见内容 + 原文图注**，不得引入图中没有的信息（典型越界：在图里"看出"产品名、凭上下文推断结论——已发生过 must-fix）。
- 无法确证时用**中性描述**（如"执行轨迹""架构示意"）或留空 alt；宁缺勿补。
- 同一稿内的描述风格保持一致。

### B4 混合型文章（公告/观点 + 教程）

What/Why（产品是什么、为什么做）归**背景**，按铁律 9 压到最小集；How（怎么做）才是教程主体，按 §3 保留。两者冲突时以**"读者能否照做"**为取舍标准。

### B5 原作者文末的 References / Citation 块 vs 缩编稿自己的「参考资料」（答复 policy-gap E-003@20261003-agents）

- **删除**：原作者文末的参考文献列表、Citation 引用块（BibTeX 等）——那是"怎样引用本文"的出处元数据，不属于作者的观点链条。E-003 已判定该删除正确，此处落成明文，免得下一轮起草方靠自行推断。
- **方向相反，互不替代**：铁律 10 的参考资料收录的是"被本稿保留下来的外部内容"的链接（本稿读者的岔路口）；原作者的 References 是"本文引了谁"（本文的出处元数据）。删掉原表的同时，被保留的内容仍按铁律 10 编号引用——两件事同稿并存是正确的，不是自相矛盾。

### B6 数学记号必须落在数学定界符内

- 原文是数学的内容，保留时必须留在 `$...$` / `$$...$$` 内，**不得脱去定界符写成裸文本**（写在图片 alt / 图注里的除外——alt 本来就是纯文本，不渲染数学）。
- 原文作者自己裸写在正文的上标记号（如 `RL^2`、`10^-3`）在数学区之外是不渲染的，**允许补一对 `$` 让它正确渲染**：属铁律 7 许可的格式修改，只包定界符、记号本身一个字符不改。
- 上下标的方向、层次、被作用对象必须与原文一致（`a_t` 不能写成 `a^t`，`x_i^2` 不能写成 `x^2_i`）。
- ** `$...$` 内出现 `\_` / `\*` 属格式损坏，不得照抄**。成因：`convert.py` 用的 markdownify 不认识 LaTeX，会把数学区的 `_` 转义成 `\_`；KaTeX/MathJax 把它渲染成**字面下划线字符**而不是下标运算符（实测见 `scripts/README.md` 附录 A）。转换后的素材已由 `convert.py` 自动还原，历史任务包用 `repair_math.py` 修复；角色发现残存的 `\_` 直接还原为 `_`，不必纠结、也不必把它当作原文内容保留。

### B7 代码块与提示词的围栏约定（围栏化 + 语言标记必须与内容相符）

- **必须围栏的内容**：源代码、命令行、配置文件、**提示词 / 系统消息 / few-shot 模板 / 结构化输出约束（JSON、schema、工具描述）**、伪代码。它们一律落在 ```` ``` ```` 围栏里与叙述文字隔开——不是排版偏好，是**保证逐字渲染**：行首的 `#` 会变成标题、`1.` 会变成列表、`<…>` 会被当成 HTML 标签吃掉、`_` 会触发斜体，只有围栏内部什么都不解析。
- **单行短模板**（一句话写得完的提示片段，如 `{Intro of an agent X}. Here is X's plan today in broad strokes: 1)`）保持行内反引号即可，不必围栏。围栏针对多行、带占位符、或带结构符号的内容。
- **同稿一致性**：原文对同类内容用了围栏的，稿件里同类都要围栏。反面实例出自 @20261003-agents 初稿：同一篇里 AutoGPT 系统消息、GPT-Engineer 两段对话/消息都围栏了，唯独 HuggingGPT 三段 Instruction 落在正文（照搬了原文的同一处不一致），读者会以为那三段不是提示词原文。
- **语言标记必须与内容相符，猜不出就留空**：

  | 内容 | 写法 |
  |---|---|
  | 真正的代码 | ```` ```python ```` / ```` ```bash ```` / ```` ```ts ```` ……按实际语言 |
  | JSON / JSON schema | ```` ```json ```` |
  | 纯文本提示词、系统消息、对话记录 | **不加标记**（```` ``` ````），要显式声明时用 `text` |
  | 拿不准 | 不加标记 |

  **提示词不要写成 ```` ```python ````**（除非它真的是 Python）：一段英文系统消息被标成 python，语法高亮会把普通英文句子当成语法错误着色，读者会去找一段根本不存在的 Python 逻辑。宁缺勿错。
- 围栏内容同样受铁律 2 约束：逐字节照抄，不重排、不"优化"缩进、不改行序。是否被逐字保留由 `verify_blocks.py` 溯源（内容须能在原文里找到；原文与本稿的 markdown 转义差异单独标注为"去转义后一致"；原文"空行分隔的散行"伪代码收进围栏后按**行级逐行一致**判定——换行规范化不算改写，2026-10-05 长文档首测落规则）。
- **围栏内的数学记号保留 `$...$` 源码形式，判合规**（v6.4，答复 @20261005-acl-long-270 E-003）：B6 说数学必须落在 `$...$` 内、B7 说伪代码必须围栏，而 LaTeX algorithm 环境的源码本来就是 `$ \mathcal{E}_{\text{pool}} $` 形态——收进围栏后 `$` 不渲染、以源码呈现，**这正是围栏"什么都不解析"的本义**，不是 B6 违规。禁止为了让它渲染而把数学脱出围栏（那才违反铁律 2）。B6 管的是叙述文字里的数学，围栏内的记号归本条管。
