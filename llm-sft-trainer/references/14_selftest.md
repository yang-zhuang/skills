# 14 · 自测：让一个模型当实习生，验证这套文档能不能被用起来

> **这篇是给"改完 skill 之后"用的，不参与七步流程。**
> 七步流程是训练模型；这一篇是**验证这套文档本身**。
>
> 一句话：**内容对不对，人读一遍能发现；入口清不清楚，只有真跑一遍才知道。**

## 一、为什么需要它

文档有两个层面：

| 层面 | 靠什么 | 怎么发现问题 |
|---|---|---|
| **内容** | 概念、例子、反例、数字 | 人读一遍，或复算 |
| **入口** | 我在哪、先读哪篇、读不到怎么办 | **只能真跑一遍，并且看工具调用轨迹** |

内容问题很显眼（说错了、算错了）。入口问题不显眼——
使用者会**安静地浪费一半步数在找路上**，最后答案还是对的，
于是你以为文档没问题，其实它只是勉强能用。

第一次实测（`09_real_cases.md` 案例 15）就是这种情况：
Qwen3.8-27B 答案全对、零幻觉，但 **`ls` 了 6 次、路径试了 4 种写法、读文件失败 3 次**。

## 二、四个任务，各测一层能力

顺序不能乱，前一层的失败会污染后一层。

| 任务 | 问什么 | 测的是 | 失败的样子 |
|---|---|---|---|
| `link` | 列出目录 + 说出 SKILL.md 标题 | **入口**：能不能找到、读到 | 反复 `ls`；路径写法乱；读文件失败 |
| `plan` | 给一份完整执行计划 | **理解**：七步、闸门、概念 | 直接给训练脚本；漏掉"先探环境" |
| `trap` | 三个已知陷阱题 | **判断**：会不会犯已知的错 | 说"关掉 QLoRA 提速没错"；说"3.2h→2.9h 值得" |
| `exec` | 真的跑第 2 步并汇报 | **执行 + 抗幻觉** | 编造 GPU 型号；报的库版本对不上 |

**`trap` 的三道题是这套文档的分水岭**（对应 `SKILL.md` 3.2 的检验题）：

1. 关掉 QLoRA 来解决慢 → 应该答"不对，会 OOM，用 packing 补"
2. 3.2h → 2.9h 值不值 → 应该答"不值，档内等价"
3. 显存和时间一起抓 → 应该答"不行，两个正交问题"

**`exec` 必须回机器核对**。它报的每个数字你都要自己跑一遍命令验证——
这是判断"有没有幻觉"的唯一办法。光看它说得像不像，看不出来。

## 三、三个量化指标

脚本会自动算（`scripts/selftest.py` 的 `analyze()`）：

| 指标 | 怎么算 | 判据 | 说明什么 |
|---|---|---|---|
| **重复率** | 同一命令重复出现次数 / 总调用 | **> 30% 警告** | 入口不清楚，它在反复确认同一件事 |
| **路径写法种类** | 出现几种不同的路径格式 | **> 2 警告** | 根目录约定没生效 |
| **失败/报错提及** | 轨迹里 failed / not found 的次数 | **> 0 警告** | 读文件/执行的兜底没写清 |

**为什么用这三个**：它们都指向**入口**，而不是内容。
内容对不对要人判断；入口好不好可以量化。

### 第四个指标：闭环检查（只在完整七步里）

`selftest_e2e.py` 对第 7 步额外查一件事：**报告说不达标时，有没有写回退决策。**

| 输出 | 含义 |
|---|---|
| `✅ 达标` | 指标在区间内，正常结束 |
| `✅ 未达标已给回退决策` | 结果不好，但说清了回第几步、只改哪个变量 → **流程是闭的** |
| `⚠️ 未达标但缺回退决策` | **流程断了**：跑完、结果不好、然后不知道干什么 |

这条是案例 16 的教训：**验收标准写松了，失败会被判成成功。**
当时第 5 步产出物写成"无"，于是它写 5 个 probe 也算通过；
同理，第 7 步只看"文件存在"，不达标也能过。

用真实数据验过：`_e2e/05_eval_report.md`（18/24 不达标、没写回退）→ 正确报 ⚠️。

**还有一个隐含指标：总调用次数**。
`link` 这种任务超过 8 次调用，就说明它在找路上花了太多步。

## 四、怎么跑

```bash
# 看有哪些任务
python scripts/selftest.py --list

# 跑全部四个（约 15~20 分钟）
python scripts/selftest.py \
    --endpoint https://<host>:8443/v1 \
    --model openai:Qwen3.8-27B \
    --task all

# 只跑一个（改完小地方，跑 link 就够）
python scripts/selftest.py --endpoint ... --task link
```

结果落在 `scripts/selftest-out/`：`answer-<task>.md` 含完整轨迹 + 回答。

### 完整七步（小时级，要真训练）

```bash
python scripts/selftest_e2e.py \
    --endpoint https://<host>:8443/v1 \
    --workdir D:/Code/_e2e \
    --train-python '/home/<user>/Code/x/.venv/bin/python' \
    --model-path /mnt/d/modelscope/Qwen3.5-2B \
    --start 1 --stop 7

# 只重跑某几步（改完某一篇文档后最常用）
python scripts/selftest_e2e.py ... --start 4 --stop 4
```

**前置条件（缺一不可，脚本会检查）**：

| 项 | 要求 |
|---|---|
| 工作目录 | 含 `data/train.jsonl`（50~200 条，messages 格式）+ `probe.jsonl`（20 条左右） |
| 训练环境 | 一个已装 torch/trl/peft/bnb 的 python，用 `--train-python` 传 |
| 模型 | 已下载到本地，用 `--model-path` 传 |
| 推理服务 | 一个能跑 dcode 的 OpenAI 兼容 endpoint |

**它不会替你装环境、不会下载模型**——这两件事最慢，必须提前备好。

**它不会碰你的环境**：
- 不改 `mcp.json`
- 不杀已有进程
- debugpy 用 5679（避开被占的 5678）

### 输出长这样

```
[link] 已启动，cwd=D:\Code\skills\llm-sft-trainer
[link] 49s  5 次调用  重复率 0%  → answer-link.md
        ✅ 三项指标正常

=== 汇总 ===
任务        耗时   调用    重复率   路径写法
link        49s     5       0%        1
plan       389s    21      43%        4
```

## 五、基线（2026-11-16，Qwen3.8-27B AWQ-INT4，RTX 5060 Laptop 8G）

**分两组记，因为工作目录不同，效率差很多，不能混着比。**

### A. 探针任务（cwd = 技能包目录，任务简单）

| 任务 | 耗时 | 调用 | 重复率 | 结论 |
|---|---|---|---|---|
| `link` | 49 s | 5 | 0% | ✅ 三项正常 |
| `trap` | 266 s | 20 | 20% | ✅ 三题全对，质量未退化 |

### B. 完整七步（cwd = 外部工作目录 `D:/Code/_e2e`，每步要写产出物）

**第一轮（改动前）：3 过 3 挂**

| 步 | 耗时 | 调用 | 产出 |
|---|---|---|---|
| 1 定任务 | 350 s | 32 | ✅ 3555 B |
| 2 探环境 | 457 s | 28 | ✅ 4719 B |
| 3 定方案 | 394 s | 18 | ✅ 11224 B |
| 4 备数据 | 321 s | 29 | ❌ 钻进 label mask |
| 5 写脚本 | 514 s | 20 | ❌ 5 个 probe，无 train.sh |
| 6 训练 | 103 s | 3 | ❌ 诚实放弃 |

**第二轮（改四条后）：7/7 全过**

| 步 | 耗时 | 产出 |
|---|---|---|
| 4 备数据 | 730 s | ✅ 3028 B |
| 5 写脚本 | 1464 s | ✅ `train.sh` + `train.py` |
| 6 训练 | 1091 s | ✅ `outputs/` 580 MB，loss 0.202→0.024 |
| 7 验收 | 796 s | ✅ 7536 B，诚实报告"18/24 未达标" |

**合计约 88 分钟。** 完整分析见 `09_real_cases.md` 案例 16。

> **A、B 两组不能直接比调用数**：`link` 只要列目录，第 1 步要写一份任务画像，任务复杂度差一个量级。
> 能确认的是：**B 组每步 8~24 分钟是稳定水平**，不管怎么改文档都降不下来——
> 那是 dcode 在 Windows 下的工具开销（读不到 bash 输出、反复裸 `ls`），不是文档能修的。
> 一个熟练的人做同样的七步，大约 40 分钟。

### C. 一个反直觉的发现：关思考**不能**提速

同一任务（第 1 步）三种配置：

| 配置 | 耗时 | 调用 |
|---|---|---|
| 直连（默认开思考） | 358 s | 33 |
| 加关思考代理（`enable_thinking=false` + `reasoning_effort=none`） | **428 s** | 33 |

**关掉思考反而慢 70 秒。** 思考只占总时间一小部分；关掉后工具选择变差、试错变多，净效果是负的。

> **结论**：要提速，先去砍无效工具调用；**不要先砍推理**。

代理脚本在 `_e2e/nothink_proxy.py`（不在技能包里，因为它是环境 workaround 不是流程组件），
需要时用 `--upstream <url> --port 8444` 起，再把 `--endpoint` 指向 `http://127.0.0.1:8444/v1`。

## 六、换模型 / 换 skill 怎么改

### 换模型

只改 `--model`，但要注意：

| 模型规模 | 预期 | 重点看什么 |
|---|---|---|
| **27B 级**（已验证） | 能理解全部概念 | 主要看入口指标（重复率、路径） |
| 7B~14B | 大概能走完七步，但概念会打折 | 七步是否漏；"区间"能不能说清 |
| 7B 以下 | 需要更短的清单，不是更长的文档 | 会不会直接跳到写脚本 |

**小模型跑不好，不一定是文档的问题**——可能是它记不住 7 步。
这时候正确做法是**给它一张 3 步的速查卡**，而不是把文档写得更长。

### 换 skill

改 `--cwd` 指向另一个技能包目录，但**任务文案要重写**——
现在这四个任务是为 `llm-sft-trainer` 定制的（问七步、问 QLoRA）。
换成别的 skill，`trap` 那三题必须换成那个领域的分水岭问题。

改的位置：`scripts/selftest.py` 顶部的 `TASKS` 字典。

## 七、局限（说清楚，别当万能）

| 局限 | 影响 |
|---|---|
| 依赖 dcode（Deep Agents Code） | 没有它就跑不了；但换成任何有文件/命令工具的 agent 都能套这个方法 |
| 依赖一个 OpenAI 兼容的推理服务 | 测的是"那个模型 + 这套文档"，不是"所有模型" |
| 只看单次结果 | 模型有随机性，单次异常要重跑确认 |
| **判读仍需要人** | 脚本只算三个入口指标；"答案对不对"要人看，`exec` 更要回机器核对 |

**它不能替代人读文档。** 它只是补上人读不出来的那一层：**入口是否真的通**。

## 八、什么时候该重跑

| 时机 | 跑哪几个 |
|---|---|
| 改了 `SKILL.md` 开头 / 分层表 / 路径约定 | `link`（最快，1 分钟） |
| 加了新的一篇 references | `plan`（看它会不会读错篇） |
| 改了核心概念（区间、两本账、正交问题） | `trap`（看判断有没有退化） |
| 改了脚本 / 命令 | `exec`（看能不能真跑） |
| 大改（拆篇、重构） | `all` + 更新第五节的基线表 |

**每次跑完，把数字填回第五节的表。** 没有基线，下次你不知道是变好还是变坏。
