# 13 · 练习：把 10、11、12 串一遍（约 30 分钟）

> 前面三篇是参考文档，这一篇是**作业**。
> 读完不算会，做完才算——做完这一遍，比读十遍文档有用。

前提：
- 按 `01_probe.md` 建好独立 venv，模型已在本地（**不要为了练习重新下载**）
- 数据用你手头任何一份 80 条左右的小样本

**时间说明（别被"30 分钟"骗了）**：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 建 venv + 装 torch/trl | **20~60 分钟** | 只做一次，不计入练习本身 |
| 下载模型 | 几十分钟到几小时 | **不要为练习下载**，用手头现成的 |
| 练习本身（跑三次 + 填表 + 算数） | **约 30 分钟** | 80 条 × 20 步，每次一两分钟 |

**如果环境还没建**，先按 `01_probe.md` 建完再来。
**如果模型还没下**，换一个你已有的、哪怕更小的模型也行——练习要的是"测出来"，不是"训得好"。

## 二、必须回答的五个问题

### 1. 1 步测速高估了多少倍？为什么？

（提示：不是"因为不准"，要说出一性次开销具体是什么）

### 2. 你的有效 token 占比是多少？低于 50% 时第一件该做的事是什么？

### 3. 按 20 步的数字，跑完 1 万条 3 epoch 要多久？换算成 GPU-hours。

（量纲要对：`s/step × 步数 ÷ 3600`）

### 4. 假设卡只有 4G，装不下现在的配置——你改哪个？

### 5. 假设时间不够，必须砍掉一半——你改哪个？

**第 4 和第 5 题的答案必须不一样。**
如果两题答了同一个手段，说明还没分清两个正交问题（`12_tradeoff.md` 第三节）。

---

## 三、判分标准

| 能答出 | 说明 |
|---|---|
| 1 步比 20 步高估 2~4 倍，且说出"一次性开销" | 懂了速度测量 |
| 算出有效率 < 30%，并提出开 packing | 懂了 padding 是纯浪费 |
| 总时长算对（±10%），量纲正确 | 会做换算 |
| 第 4 题选 QLoRA / ckpt / offload / 降 bs | 知道**省显存**用哪套 |
| 第 5 题选 packing / 快 kernel，且**没有撤掉 QLoRA** | **懂了两个正交问题** ← 最重要 |
| 第 5 题答"把 QLoRA 关掉" | **没懂**：关掉就 OOM，回到原点 |
| 任何一题答"调 learning rate" | 没懂：它既不省显存，也几乎不提速 |

**第 5 题的陷阱说明**：
如果你第 4 题上了 QLoRA，第 5 题又想省时间，正确做法是**在保留 QLoRA 的前提下**开 packing；
不是"既然要快，那就别用 QLoRA 了"。后者会让显存立刻爆掉——**两个问题不能互相抵消**。

## 四、加一道现实题（这题最能看出有没有想清现实）

> 你只有 1~2 次训练机会（跑一轮几小时），没有"先试三档再挑"的余地。
> 在开跑之前，你做什么来保证这次不废？

**标准答案**：跑一次 smoke test（30 步，几分钟），拿到真实显存 + 真实 s/step，
确认两个都在档内，再开全量。

答"先把三档都跑一遍对比"的，说明还在用理想情况思考——
**你没有那个时间，也没有那么多卡时**（`11_scope.md` 第二节）。

## 七、常见错误（都是真的有人犯过）

| 现象 | 说明什么 | 去看 |
|---|---|---|
| 用 1 步的数字估总时长 | 不懂一次性开销 | `10_measure.md` 1.2 |
| 20 步用了两个不同的计时字段 | 口径混用 | `10_measure.md` 1.3 |
| loss 降到 0.05 就说"训得很好" | 把 loss 当精度 | `10_measure.md` 2.1 |
| 显存明明够还上 QLoRA | 没判断卡在哪个区间 | `11_scope.md` 第五节 |
| 嫌 QLoRA 慢，关掉换 LoRA | 两个正交问题没分清 | `12_tradeoff.md` 第三节 |
| 为 3.2h→2.9h 折腾半天 | 不懂档内等价 | `11_scope.md` 第一节 |
| 表里列了"多卡""换模型" | 没考虑自己的现实 | `11_scope.md` 第二节 |
