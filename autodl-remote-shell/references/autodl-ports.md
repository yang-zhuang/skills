# AutoDL 端口映射与公网访问

## 目的

说清「实例内的服务怎样才能从公网访问」——AutoDL 只对外暴露固定端口，
任何监听在其它端口的服务（哪怕进程正常、本机 curl 通）**外网一律访问不到**。

---

## 端口映射规则

平台在实例内只映射 **两个端口**：`6006` 与 `6008`。控制台给出的形态如下：

```
您在实例中监听6006和6008端口的服务，系统将映射此端口到以下公网地址供您访问。
默认将以http协议进行映射，如需修改请关机后在规格详情中进行修改。

服务地址：
http://127.0.0.1:6006 → https://<随机串>.<区域>.seetacloud.com:8443
http://127.0.0.1:6008 → https://<随机串>.<区域>.seetacloud.com:8443
```

拆解成可执行结论：

| 要素 | 要求 |
|---|---|
| 实例内监听端口 | **必须是 6006 或 6008**，其它端口不会被映射 |
| 实例内监听地址 | `127.0.0.1`（如上交所出即为本地回环地址即可） |
| 公网访问地址 | `https://<随机串>.<区域>.seetacloud.com:8443`（每台实例不同，以控制台为准） |
| 协议 | 默认 **http** 映射；改为 https 等需**关机**后在「规格详情」里修改 |
| 可用端口数量 | **只有 2 个**，同时暴露的服务最多 2 个 |

---

## 必须显式改端口的典型服务

很多服务的默认端口都不在白名单里，**不修改就外网访问不到**：

| 服务类型 | 常见默认端口 | 需改为 |
|---|---|---|
| Strata 推理服务 | 8080 | **`--port 6006`** |
| Gradio 前端 | 7860 | `--server-port 6006` |
| FastAPI / Uvicorn | 8000 | `--port 6006` |
| Ollama | 11434 | 设为 `6006` |
| vLLM OpenAI API | 8000 | `--port 6006` |

### 实例：Strata 必须指定 6006

Strata 的服务默认端口是 **8080**，直接启动后外网无法访问。
启动时要显式指定端口（同时可用 `--host` 控制监听范围）：

```bash
./setup.sh --port 6006
```

> 这是本次实操里真实踩到的情况：引擎编译好了、服务也起了，但因为端口不对，外网仍打不开。

---

## 排查流程

按下面顺序确认，可在 1~2 条短命令内定位问题：

### 1）服务是否真的在 6006/6008 上监听

```bash
ss -tlnp 2>/dev/null | grep -E '6006|6008'
```

没有输出 → 服务没监听在这两个端口上，**必须改服务端口**。

### 2）实例内部先自检（排除服务本身故障）

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:6006
# 有健康检查端点的服务：
curl -sS http://127.0.0.1:6006/health
```

本机都打不通 → 服务自身有问题，与端口映射无关。

### 3）外部用控制台给出的公网地址访问

```
https://<控制台给出的随机串>.<区域>.seetacloud.com:8443
```

上面 1、2 都通过而外网仍不通 → 检查控制台这条映射是否启用、协议是否为期望的 http。

> 一键体检可用 `scripts/autodl-port-check.sh`。

---

## 注意事项

- **端口是稀缺资源**：只有 2 个。规划哪个服务占 6006、哪个占 6008，别等到冲突了再挪。
- **后台长驻服务也要后台化**：启动推理服务这类常驻进程时同样用 `setsid ... > log 2>&1 &`，
  否则命令返回时进程可能被终止（参见 `shell-mcp-usage.md`）。
- **改协议要关机**：默认是 http 映射，协议调整需在**关机状态**下于「规格详情」里修改，运行中是改不了的。
- **别用 `0.0.0.0` 滥用暴露**：按控制台给出的映射说明，监听 `127.0.0.1:6006` 即可；
  对外网开放范围应通过 `--host` 谨慎控制，必要时配合 API key。

## 外网 403：DNS rebinding 保护（实测）

网络打通后仍可能拿到 **HTTP 403**，错误体类似：

```json
{"error": {"type": "forbidden", "message": "Host '<随机串>.<区域>.seetacloud.com' is not allowed
 (DNS rebinding protection). Reaching Strata under this name on purpose? Add it to
 \"allowed_hosts\" in the config (strata-<model>.json) or to the STRATA_ALLOWED_HOSTS
 environment variable, or set an API key (\"api_key\"), which turns this check off"}}
```

**这不是网络问题**（能收到这个响应本身就说明链路通了），而是服务端的主机名白名单检查。

解法二选一：

1. 把公网主机名加进配置的 `allowed_hosts`（数组），例如 Strata 的 `strata-<model>.json`：

   ```json
   "allowed_hosts": ["<6006 的公网域名>", "<6008 的公网域名>"]
   ```

2. 设置 API key（更安全，且会一并关掉该检查）。

改完配置需**重启服务**才生效。

## 重启大模型服务：端口不会立刻释放

杀掉进程（`kill <PID>`）后，**模型卸载需要时间，端口仍被占用一段时间**。
此时立刻启动新实例会失败：

```
server.py: error: port 6006 is already in use - is Strata (or another server) already running?
```

而旧进程随后也会退出，结果变成「新旧都没了」，外网访问返回网关的通用 404 页面。

**正确做法**：重启前先确认端口确实空闲（见 `scripts/autodl-port-check.sh`，
它已内置 `ss` / `netstat` / `/proc/net/tcp` 三级回退），再启动新进程。

---

## 安全提醒

`api_key` 未设置时，服务对**任何拿到公网地址的人**开放（`/health` 会显示 `"api_key": false`）。
AutoDL 的公网地址一旦泄露即可被他人调用，产生算力开销。建议对外暴露时设置 API key。
